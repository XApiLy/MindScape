# DeepSeek Harness 与 MindScape 集成讨论提案

> 状态：待决策，不是 V1 已确认范围
>
> 日期：2026-08-16

## 1. 当前判断

MindScape 可以借鉴或接入 DeepSeek Harness，但不应把 Harness 代码直接塞进 MindScape 内核，也不应让 Harness 的内部对象反向定义 MindScape 的会话、上下文、事件或证据语义。

建议定位：**Harness 是可插拔的模型运行与实验执行后端；MindScape 是认知工作空间和可追溯会话图。**

在没有确认具体仓库地址、许可证、运行边界和 API 版本前，本提案只讨论架构关系，不承诺兼容某个具体 Harness 实现。

## 2. 两者的职责边界

| MindScape | Harness 后端 |
|---|---|
| 会话图、分支、节点和关系 | 模型执行循环与运行编排 |
| ContextSnapshot 冻结和上下文选择 | 提示、工具、重试或策略的执行 |
| Skill / MCP 挂载与权限 | 在授权范围内调用工具和处理工具返回 |
| 原文轨、接续轨、分析轨和证据 | 运行轨迹、步骤、工具事件和评测数据 |
| 统一 ModelRunEvent 与事件账本 | 将自身事件映射为统一运行事件 |
| 画布、Chat、透明工作轨迹和用户控制 | 具体模型或开源运行时的执行细节 |

Harness 产生的轨迹必须作为可观察运行证据或派生数据保存，不能替代 MindScape 的领域事实。

本提案中的“执行”仅指服务于高质量会话的认知执行，例如检索、阅读、比较、计算、引用、结构化、验证和成果整理。它不包括自主修改代码仓库、操作终端、运行测试、提交代码、部署软件或控制用户本地桌面。Harness 若主要服务于编程 Agent 或本地工作 Agent，MindScape 只借鉴其中可复用的上下文、轨迹、验证和评测能力，不承接其代码执行面。

## 3. 最有价值的结合点

### 3.1 作为第二种运行模式

普通聊天默认走直接 Provider，减少延迟和 Token 成本；复杂探索、工具调用、模型对比或需要完整运行轨迹时，用户选择 Harness 模式。

```text
ContextCompiler
    -> ModelRunRequest
        -> RuntimeGateway
            -> DirectProvider
            -> DeepSeekHarnessAdapter
    -> Unified ModelRunEvent
        -> Event Ledger
        -> Chat / Canvas / Evidence Projection
```

MindScape 不改变上层调用协议，Harness 只是 Provider Runtime 的一种实现。

### 3.2 运行轨迹透明化

如果 Harness 能提供工具调用、步骤、重试、验证、错误和最终结果，MindScape 可以把它们展示为可审计工作轨迹：

- 输入了哪些上下文。
- 挂载了哪些 Skill / MCP。
- 调用了哪些工具。
- 工具返回了什么证据。
- 哪些步骤失败或重试。
- 最终结论依赖哪些证据。

这些是可验证事件，不等于模型不可获得的隐藏 Chain-of-Thought。产品文案必须继续区分“原生运行事件”“Provider 提供的摘要”和“MindScape 重建的证据关系”。

### 3.3 轨迹导入与回放

Harness 的运行记录可以作为一种外部会话或运行轨迹导入：

- 原始 Harness 轨迹进入原文轨。
- 结构化步骤、工具结果和失败状态进入派生接续轨。
- 用户可以在画布上从某个步骤分支继续。
- 导入报告明确哪些状态恢复、部分恢复或无法恢复。

这会直接增强 MindScape 的“接手其他 AI 工作”能力，但不能承诺重新运行后得到逐字相同结果。

### 3.4 多策略实验

同一个冻结 ContextSnapshot 可以分别用直接 Provider、Harness 策略和不同 Skill 组合运行，结果作为平行分支比较。这样 Harness 不只是“接了一个模型”，而是成为 MindScape 的可控认知实验后端。

## 4. 不应该做的事情

- 不要 fork 整个 Harness 并让它成为主仓库唯一运行方式。
- 不要让 Harness 的内部 session、message、trajectory ID 进入 MindScape 领域契约。
- 不要让画布组件直接消费 Harness 原始事件。
- 不要默认所有会话都走 Harness，避免无意义的延迟、成本和复杂度。
- 不要把 Harness 的执行轨迹包装成模型原始隐藏思维链。
- 不要在桌面端第一阶段执行未经审计的任意 Harness 代码、脚本或网络工具。
- 不要在没有许可证、沙箱、权限、超时、取消和数据边界审查前引入第三方运行时。
- 不要因为 Harness 具备代码或系统执行能力，就把 MindScape 扩张为 AI IDE、CLI Agent 或通用本地工作智能体。

## 5. 建议的集成顺序

### 阶段 0：项目核对

确认具体仓库、许可证、运行环境、输入输出协议、工具权限、事件格式、模型支持和安全假设。没有这些信息前，不做代码级兼容承诺。

### 阶段 1：只做适配器

实现 `HarnessProviderAdapter` 或等价边界，将 Harness 请求和事件转换为现有 `ModelRunRequest` / `ModelRunEvent`。不修改会话图、ContextSnapshot 和画布领域模型。

### 阶段 2：做对照实验

使用 10～20 个脱敏任务比较直接 Provider 与 Harness：成功率、首 Token 延迟、总延迟、Token、费用、工具成功率、取消可靠性、失败恢复和用户是否理解轨迹。

### 阶段 3：决定是否深入

只有当 Harness 在可验证质量、运行透明度或工具编排上产生明确增量，才考虑加入本地实验室、轨迹回放或更深的运行集成。若只增加复杂度，不进入 V1。

## 6. 需要用户和团队确认的问题

1. 你指的具体 DeepSeek Harness 仓库地址和当前版本是什么？
2. 它是模型运行框架、Agent Harness、评测工具，还是某个社区项目的统称？
3. 它的许可证是否允许 MindScape 作为依赖、服务或商业产品的一部分使用？
4. 它是否支持结构化流式事件、取消、超时、工具权限和运行恢复？
5. 我们希望优先获得的是运行能力、轨迹透明、模型评测，还是开源生态影响力？

在这些问题确认前，唯一建议锁定的是“适配器边界”，不是具体实现。

## 7. 能力、收益与代价

### 7.1 可以增加的用户功能

- **运行模式选择**：普通直连、Harness 执行和多方案对比。
- **自动工具工作流**：AI 在权限范围内组合 Skill、MCP、搜索、文档和内部认知工具。
- **可观察运行轨迹**：显示上下文、工具、证据、重试、验证、失败和最终结果。
- **暂停、取消、恢复与重放**：长任务不再只有一个不可解释的最终回答。
- **平行实验分支**：相同 ContextSnapshot 使用不同模型、策略或能力组合并排比较。
- **轨迹导入**：外部 Harness 运行记录进入原文轨和派生轨，并可从指定步骤继续。
- **评测与复现**：保存运行配置、能力版本、输入快照、事件和结果，形成可回放样本。

### 7.2 对 MindScape 的核心提升

MindScape 会从消息管理和聊天画布，提升为可追溯的认知运行工作区。画布上的节点不再只代表一问一答，还可以代表一次带上下文、工具、证据、验证和运行状态的完整 AI 工作。

主要提升包括：复杂任务完成率、工具调用可靠性、结果可解释性、失败可恢复性、跨模型比较能力和运行样本积累。模型能力增强时，Harness 可以利用更强的规划、工具和验证能力，而 MindScape 的会话图、证据和用户控制继续复用，符合“AI 越强，产品越强”的原则。

### 7.3 产品与商业收益

- 与普通聊天产品形成差异：不是更多按钮，而是可运行、可回放、可比较的 AI 工作过程。
- 开源运行时可以降低早期自研执行框架的成本，并吸收社区适配器、工具和评测方法。
- 统一轨迹可以逐步形成 MindScape 自己的评测数据、工作流模板和认知资产。
- 用户可以在高复杂度任务上选择更强执行，在简单聊天上保持低成本，覆盖不同使用深度。

### 7.4 主要缺点与风险

- **复杂度增加**：运行状态、工具权限、重试、恢复、沙箱和版本兼容都会扩大工程面。
- **延迟与成本增加**：多步骤规划、工具和验证会消耗更多 Token 和时间，不适合所有聊天。
- **安全面扩大**：文件、网络、MCP、脚本和第三方工具都可能引入数据泄漏与越权风险。
- **状态双重来源**：若边界不严格，Harness 和 MindScape 会各自维护 session、message 和任务状态，最终无法恢复。
- **供应链与许可证风险**：开源不等于可以无条件商用，也不代表依赖、模型权重和工具都具备相同许可证。
- **上游变化风险**：热门开源项目迭代快，内部 API 和事件格式可能不稳定。
- **体验变复杂**：直接把步骤、日志和配置暴露给普通用户，会破坏 MindScape 简洁模式。
- **伪透明风险**：运行轨迹可以验证，但不能被宣传为模型真实隐藏思维链。
- **模型偏置风险**：若 Harness 对 DeepSeek 的提示和工具策略高度优化，可能削弱 MindScape 的模型无关定位。

### 7.5 推荐的产品结论

不把 Harness 设置为默认路径，也不阻塞当前 V1。先做一个独立技术验证：同一批任务分别使用直接 Provider 和 Harness，只有在质量、轨迹价值或恢复能力产生可验证增量时，才进入正式产品范围。

最终形态应是“简单用户感受不到 Harness 的存在，高级用户可以展开全部运行轨迹和控制项”。

无论是否接入 Harness，MindScape 的最终产品判断标准都不是“能否像编程 Agent 一样替用户操作环境”，而是“是否让会话更准确、更连续、更可理解、更可探索、更可管理”。凡是不能明显提升这五项指标的 Harness 能力，都不进入产品。
