# MindScape V1 安全威胁模型

> 状态：RC1  
> 负责人：员工01；员工02、员工05必须评审  
> 对应任务：ARC-013

## 1. 保护目标

- API Key 和安全凭据。
- 用户会话正文、导入原文件、附件与证据引用。
- 会话图、上下文快照和事件账本的完整性。
- 数据删除范围、迁移与备份的可恢复性。
- 模型请求范围和外部副作用的用户控制权。

## 2. 信任边界

```text
不可信导入文件 / 模型输出 / Provider响应
                    ↓
Tauri命令与适配器边界
                    ↓
应用服务与领域校验
                    ↓
SQLite / 原文件存储 / 操作系统凭据
```

React UI、模型输出、导入内容和网络响应均不被视为权威输入。领域命令必须再次校验。

## 3. 主要威胁与控制

| 威胁 | 风险 | 必需控制 |
| --- | --- | --- |
| 明文 Key 泄漏 | 账户与费用损失 | Key 仅进入操作系统凭据；日志和错误统一脱敏 |
| 导入提示注入 | 历史内容诱导执行命令 | 导入一律作为数据；不自动执行其中指令和工具调用 |
| 路径穿越 | 读取或覆盖工作区外文件 | 规范化路径；原文件写入限定内容寻址目录 |
| 恶意超大文件 | 内存、磁盘或界面拒绝服务 | 大小、数量、解压比、解析时间和并发上限 |
| 伪造 Provider 成功 | 用户相信未完成操作 | 失败必须为 `failed`；禁止错误转普通回答 |
| 重试重复计费 | 重复模型调用 | 幂等键、明确重试策略；流式开始后默认不自动重试 |
| 上下文越界发送 | 私人内容被意外上传 | 运行前冻结并可查询发送范围；Provider只消费快照 |
| SQL/事件篡改 | 会话关系或证据失真 | 参数化查询、外键、事务、迁移、追加事件和完整性测试 |
| 不明确删除 | 原文件或派生层误删 | 删除命令显式列出范围；原文与派生分开处理 |
| 错误信息泄密 | 原始响应携带敏感信息 | `ProviderError.safeMessage` 白名单字段；原正文不跨 UI 边界 |

## 4. 硬失败条件

以下任一出现即阻断发布：

1. 数据库、localStorage、日志或崩溃报告中可检索到完整 API Key。
2. 导入内容能未经用户确认触发命令、工具或外部发送。
3. UI 或 Provider 可以绕过 ContextSnapshot 直接拼接历史。
4. 删除会话会静默删除用户未确认的原文件范围。
5. 迁移失败会覆盖唯一原数据库或无法回退。
6. Provider 失败被记录为成功回答。
