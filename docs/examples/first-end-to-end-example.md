# MindScape 第一个端到端示例

> 目的：用一个短案例说明系统如何工作。  
> 场景：导入 Claude / Codex 中关于 NeoCarry 的历史讨论，并继续推进。

## 1. 用户看到的入口

用户把一个导出的会话文件拖入 MindScape，并看到：

```text
已导入 1 个会话，来自 Claude
共 42 轮消息，包含 3 个代码片段和 1 个附件

你想怎么处理？
[继续这次工作] [并入项目] [提炼成果] [漫游分析] [仅归档]
```

用户点击“继续这次工作”，随后选择分析档位：

```text
如何接续？

( ) 原样继续      不进行 AI 分析；全量携带可能增加后续每轮消耗
(●) 快速识别      提取目标、最后进展和下一步
( ) 详细分析      理解完整脉络、决策和工具调用
( ) 漫游分析      按分析配方扫描全部资料

推荐“快速识别”：会话较长，最近结论分散在多条消息中。
预计消耗：一次性约 8k 输入 Token；不包含附件和工具输出。
预计收益：后续每轮少携带约 20k 历史上下文，可随时查看原文。
```

用户无需先配置 Skill，也可以选择“原样继续”。本示例选择“快速识别”。

## 2. 导入内容的关键片段

历史对话中有这些内容：

```text
用户：NeoCarry 想做成一个帮助开发者管理 AI 编程上下文的工具。

Claude：可以先做全局剪贴板、代码片段管理、多个模型切换和项目知识库。

用户：我最担心的是范围太大，第一版不知道先做什么。

Claude：建议先从剪贴板开始。

Codex：已经创建了 clipboard 原型，支持保存文本，但还没有来源追踪和项目归属。
```

## 3. MindScape 的快速识别

系统先做低成本扫描，只展示最少但有用的信息：

```text
识别：这是一次产品范围收敛与开发路线讨论。

关键问题：第一版范围过大，且“先做剪贴板”的依据不足。

建议：先比较 3 个候选切入点，再决定 MVP；暂不分析全部历史。

已找到：产品目标、候选功能、一个已有原型、一个范围风险。
```

此时系统没有：

- 把 42 轮消息全部总结。
- 自动读取整个代码仓库。
- 自动运行 Codex 历史中的命令。
- 一次性装载十几个 Skill。

## 4. 两个指标如何筛选内容

系统内部可以得到这样的粗粒度判断，普通用户默认不必看到分数：

| 片段 | 目标相关度 | 决策价值 | 动作 |
| --- | --- | --- | --- |
| NeoCarry 的产品目标 | 高 | 高 | 深入分析 |
| “先做剪贴板”的建议 | 高 | 高 | 深入分析并检查依据 |
| 已创建的 clipboard 原型 | 高 | 高 | 读取摘要与文件状态 |
| Claude 的客套解释 | 中 | 低 | 压缩 |
| 早期被否决的颜色方案 | 低 | 低 | 暂不分析 |
| 未执行的 Codex 命令 | 中 | 高 | 标记为历史工具记录，不执行 |

## 5. 自动挂载的能力

MindScape 只挂载当前最小组合：

```text
已挂载
✓ 产品范围收敛
✓ 项目状态读取
✓ 决策记录

建议但未启用
○ 代码库概览
○ 技术风险评估

未授权
× 文件写入
× 终端执行
```

界面展开后可以查看理由：

```text
产品范围收敛
依据：历史对话多次提到“第一版不知道先做什么”
作用：比较候选切入点并形成 MVP 边界
生命周期：当前阶段
```

## 6. MindScape 发送给主 AI 的上下文

主 AI 不接收 42 轮原文，而收到一个带来源的上下文包：

```text
当前目标：确定 NeoCarry 的第一版切入点
当前阶段：方案比较 / 范围收敛
已知约束：团队规模小；已有 clipboard 原型；不能同时做完整知识库、模型平台和桌面录制
关键证据：导入会话第 3、18、31、40 轮
已确认事实：clipboard 原型已经存在，但只有文本保存
待解决问题：剪贴板是否足以成为用户愿意持续使用的核心入口
期望交付：三个候选方案的比较、推荐方案、风险和下一步
```

## 7. AI 的第一版回答

```text
先不要直接把“剪贴板”定为产品核心。当前有三个候选切入点：

1. 智能剪贴板：实现最快，但容易被理解成普通工具，差异化不足。
2. AI 会话迁移与上下文续接：能直接利用已有 Claude/Codex 工作，差异化更强，但需要先处理导入格式和上下文编译。
3. 项目讨论工作台：价值上限高，但首版范围和交互成本最大。

推荐：先做“会话迁移 + 上下文续接”的垂直闭环，剪贴板作为第二入口。

依据：
- 你已有的痛点是跨 AI 丢失上下文，而不是单纯缺一个剪贴板。
- 现有原型可以复用，但不能因此反过来决定产品方向。
- 该方案能在不实现完整项目管理器的前提下验证 MindScape 的核心价值。

下一步：提供一个 Claude/Codex 导入文件，生成续接上下文，并让用户在新模型中完成一次真实推进。
```

回答中的“推荐方案”可以被识别为候选决策，但不会自动写成已确认决策。

## 8. 用户纠正系统

用户说：

```text
我不同意先做会话迁移。NeoCarry 的第一批用户根本没有导出会话的习惯，必须先从全局捕捉开始。
```

系统记录一条高优先级用户纠正：

```text
纠正：目标用户没有主动导出会话的习惯
影响：会话迁移不能作为第一入口；全局捕捉的优先级上升
证据：用户明确表达
状态：已确认，等待后续验证
```

然后系统重新计算，而不是坚持原来的推荐：

```text
当前阶段：用户入口选择
重新挂载：用户研究、入口设计、MVP 验证
暂时移除：会话迁移深度设计
保留：产品范围收敛、决策记录
```

新的回答变成：

```text
接受这个前提。那我们不把“导入会话”当作首要入口。

新的 MVP 可以是：
1. 全局快捷键捕捉 AI 回复或屏幕内容。
2. 自动保存来源和时间。
3. 选中内容后询问 AI“这段内容对 NeoCarry 项目意味着什么”。
4. 将结果加入项目上下文。

会话导入仍然保留为第二入口，用于迁移已有深度工作。
```

## 9. 什么时候使用漫游分析

如果用户改为点击“漫游分析”，系统不再围绕一个单一问题收敛，而是使用默认配方扫描完整资料：

```text
漫游分析发现：
- 目标在“开发者工具”和“AI 工作空间”之间摇摆。
- 剪贴板是现有原型，不等于用户需求已经验证。
- 会话迁移是差异化能力，但依赖用户主动导出。
- 全局捕捉可能降低首次使用门槛，但需要桌面权限。
- “跨 AI 上下文”在多个会话中重复出现，是稳定痛点线索。

待确认：
- 首批用户是否愿意授予全局捕捉权限？
- 捕捉后最常见的下一步是保存、询问 AI 还是加入项目？
```

漫游分析不会替用户直接决定路线，只会把跨资料发现、证据和待确认问题整理出来。

## 10. 这个示例验证了什么

- 简单用户只需要看到“识别、关键问题、建议”。
- 高级用户可以展开评分依据和完整能力变化。
- AI 保持自由回答，没有被学习模式或项目模式限制。
- Skill 是按阶段挂载的，可以在用户纠正后重规划。
- 历史会话被理解，但没有被整段粗暴塞进上下文。
- 漫游分析是显式的广域探索，不是默认 Token 黑洞。
- 用户确认的结论、系统推断和待验证线索彼此分离。

这个案例目前是验收样本，不代表最终 UI 或最终评分权重。
