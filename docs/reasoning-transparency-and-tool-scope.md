# MindScape 透明推理与工具边界

> 状态：产品原则与交互草案  
> 最近更新：2026-08-14

## 1. 透明性的准确承诺

MindScape 不承诺展示 AI “脑中每一个真实念头”。多数模型接口不会返回完整隐藏思维链，即使要求模型事后写出推理过程，也只能得到一种解释文本，不能证明它就是实际内部计算过程。

产品能够可靠承诺的是：

> 展示 AI 完成任务时可观察、可记录、可验证的完整工作轨迹，并让最终逻辑能够回溯到输入、证据和工具结果。

这比滚动显示一大段不可验证的“思考中……”文字更有价值。

## 2. 用户可以看到什么

### 实时活动轨迹

```text
正在理解：比较量子纠缠与经典相关性
选取上下文：本会话 4 个片段、导入论文 2 个章节
挂载能力：概念对比、论文引用核验
调用工具：论文检索、术语关系图
形成判断：发现 1 个容易混淆的前提
正在验证：检查结论是否被原文支持
```

每一步都来自真实系统事件，不生成虚假的活动动画。

### 逻辑证据图

使用以下节点：

- 用户目标
- 已确认事实
- 来源证据
- 假设
- 中间判断
- 备选解释
- 反例与冲突
- 最终结论
- 未解决问题

使用以下关系：

- 支持
- 反驳
- 依赖
- 推导自
- 限制
- 待验证

例如：

```text
[论文原文 A] ─支持→ [纠缠产生非经典相关性]
[无信号定理] ─限制→ [不能借此超光速通信]
[常见误解] ─反驳→ [纠缠等于即时传递信息]
                         ↓
                    [最终解释]
```

### 工具调用记录

每次工具调用展示：

- 为什么调用。
- 使用了哪些输入和数据范围。
- 是否将数据发送到云端。
- 工具返回了什么。
- 耗时和失败状态。
- 哪个结论引用了结果。
- 是否产生了可撤销的内容变化。

涉及密钥、私人数据和内部安全信息时只展示经过脱敏的摘要。

### 上下文账单

用户可以查看本轮 AI 实际获得了什么：

```text
会话目标                         320 tokens
最近消息                       1,840 tokens
导入会话接续包                   960 tokens
论文关键片段                   3,200 tokens
概念对比 Skill                   680 tokens
省略内容：17 个低相关片段
```

这样可以审计“AI 为什么知道这些、为什么不知道另一些”。

## 3. 不同模型的透明度标签

- **系统事件**：MindScape 实际记录的上下文选择、工具调用和状态变化。
- **模型推理摘要**：由模型提供商明确返回的推理摘要。
- **可验证依据重建**：MindScape 根据答案、来源和工具结果生成的逻辑说明。
- **模型自述**：模型在回答中自行描述的方法，不视为内部过程证据。

界面不能把四者混在一起。

## 4. 如何检查逻辑自洽

回答完成后可以运行轻量验证：

1. 将关键结论拆成可检查陈述。
2. 为每项陈述查找直接证据或标记为推断。
3. 检查结论之间是否互相冲突。
4. 检查是否违反用户明确约束。
5. 搜索最强反例或备选解释。
6. 标注仍然无法确定的部分。

验证结果不应伪装成绝对正确：

```text
结论完整度：4/5 项有直接依据
发现冲突：1 项
未验证假设：2 项
引用状态：全部可回溯
```

## 5. 渐进披露

普通用户默认只看到一行：

```text
已参考 6 项资料 · 使用 2 个工具 · 发现 1 个不确定点
```

展开后看到时间线，再进一步进入逻辑证据图和完整审计。用户可设置：

- 简洁：只显示结论、来源和警告。
- 标准：显示活动轨迹与工具调用。
- 专家：显示上下文账单、能力变化、证据图和验证记录。

透明能力完整存在，但不会强迫所有用户阅读复杂过程。

## 6. MindScape 的工具面

MindScape 工具围绕认知工作，而不是软件工程落地。

### 信息获取

- 搜索与网页阅读
- 文档、PDF、图片和音视频理解
- OCR、翻译与术语对照
- 外部会话导入

### 理解与探索

- 本地与云端知识检索
- 来源核验与交叉对比
- 计算器、公式与单位换算
- 时间线、关系图和数据可视化
- 概念解释、测验与反例生成

### 组织与沉淀

- 创建卡片、分支和知识节点
- 高光、笔记、标签和引用
- 更新项目上下文、决策和未解决问题
- 生成提纲、总结、报告和演示材料
- 云同步、分享和导出

## 7. 不属于核心工具面的能力

第一阶段不提供：

- 通用终端和任意命令执行
- 自主修改代码仓库
- 自动测试、调试和提交循环
- 部署与发布软件
- 长时间无人监督的系统操作

MindScape 可以解释代码、阅读用户提供的技术资料、生成示例或讨论架构，但不将这些能力扩展为 IDE 级执行代理。

## 8. 任意内部工具调用的含义

所有内部工具都注册到统一目录，向 AI 声明：

```text
工具名称
用途
输入结构
输出结构
读取的数据范围
是否访问云端
是否修改工作空间内容
是否可撤销
费用与时间成本
```

AI 可以根据当前任务发现和组合任何已注册工具。权限分为：

- **无副作用**：计算、检索和只读分析，可按用户策略自动调用。
- **可撤销内部变化**：创建卡片、添加高光、更新图谱，可自动或先预览。
- **外部或不可逆变化**：分享、发送、删除和公开发布，必须明确确认。

工具调用失败时，AI 必须知道真实失败结果，不能继续假装已经获得数据。

## 9. 最小可行版本

第一版透明轨迹只需覆盖：

1. 当前目标。
2. 使用的上下文片段。
3. 挂载的 Skill。
4. 工具调用及结果。
5. 结论与引用关系。
6. 不确定项和验证结果。

首批工具只做：

1. 网页搜索与阅读。
2. 文档导入与检索。
3. 会话内引用与高光。
4. 卡片和分支创建。
5. 关系图生成。
6. 计算与简单可视化。

先证明 AI 能在一轮探索中自主组合这些工具，并让用户完整看懂其依据，再扩大工具目录。
