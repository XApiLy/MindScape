# MindScape 第一版产品规划与范围边界

> 文档性质：第一版唯一有效的产品范围基线  
> 版本：V1.0 Draft  
> 日期：2026-08-14  
> 负责人：产品负责人 / 总经理  
> 适用团队：产品、设计、前端、桌面端、后端、AI、测试

## 1. 管理层结论

MindScape 第一版只完成一个清晰闭环：

> 用户可以直接开始一段 AI 会话，或导入其他 AI 平台的历史会话，在无限画布中保留上下文与分支关系，并选择不同厂商模型继续工作。

第一版由四个核心能力和三个必要支撑能力组成。

### 四个核心能力

1. 无限会话画布。
2. 外部 AI 会话导入器。
3. 多厂商模型 API 接入。
4. 基础 Chat。

### 三个必要支撑能力

1. 工作区、会话和本地数据保存。
2. 密钥、安全、错误与恢复机制。
3. 不依赖教程的首次使用体验。

除上述范围外的长期能力不进入第一版发布承诺。第一版追求闭环完整、稳定、可理解，不追求功能数量。

## 2. 第一版不是最终产品的缩小版

MindScape 的长期方向包括动态 Skill、MCP、认知工具编排、透明工作轨迹、漫游分析、成果资产化、知识生态和 HyperPhase 内容捕捉。但这些能力同时进入开发，会导致团队在没有验证核心交互前建设多个复杂系统。

第一版只验证三个核心假设：

1. **画布假设**：用户是否真的比在线性聊天列表中更容易理解、分支和继续复杂会话。
2. **迁移假设**：用户是否愿意把其他 AI 平台中的重要会话带入 MindScape 并继续工作。
3. **模型无关假设**：在同一个上下文和画布中切换模型，是否构成稳定、可感知的产品价值。

如果这三个假设不成立，后续再多的 Skill、工具和生态都无法形成可靠基础。

## 3. 目标用户

第一版优先服务已经频繁使用 ChatGPT、Claude、Gemini、DeepSeek 或 Codex 的中高频 AI 用户。他们通常具有以下特征：

- 同时使用两个或更多 AI 平台。
- 进行长对话、研究、学习、项目讨论或内容创作。
- 经常遇到历史上下文丢失、分支混乱或平台切换后需要重新解释的问题。
- 希望控制模型、上下文和费用，但不希望先学习复杂配置。

第一版暂不优先服务：

- 只进行一次性简单问答的轻度用户。
- 需要企业级多人权限、审计和知识库管理的组织客户。
- 期待软件自动修改代码、运行终端和部署项目的 AI IDE 用户。

## 4. 核心使用场景

### 场景 A：从零开始探索

用户输入一个自然语言问题，选择模型并获得回答。回答成为画布根节点，用户可以继续深入、创建平行视角或换一个角度。

### 场景 B：导入并继续旧会话

用户导入 Claude、ChatGPT、Codex 或通用会话文件，查看解析完整度，选择原样继续、快速识别或详细分析，然后在画布中继续工作。

### 场景 C：在关键节点分叉

用户从任意问答节点创建新分支。新分支知道自己的来源，但不会污染原分支。用户可以在不同方案之间来回查看。

### 场景 D：更换模型继续同一问题

用户在同一个节点上下文上选择另一个模型继续提问或生成平行回答，并清楚看到本次使用的厂商与模型。

## 5. 产品原则

### 5.1 不设置模式牢笼

第一版不强迫用户先选择“学习、项目、开发、创作”等模式。用户可以直接输入自然语言。会话类型只作为未来的可编辑辅助信息，不限制模型回答。

### 5.2 AI 与平台能力并行

MindScape 不替代模型的推理能力。平台负责组织上下文、保存关系、提供工具和控制边界。模型越强，产品能够利用的能力越强。

### 5.3 原始内容不可变

导入会话的原始文件和原始消息不得被摘要、纠错或分析结果覆盖。所有分析都是可删除、可重建的派生层。

### 5.4 简单默认，复杂可展开

普通用户默认只需输入问题、选择模型和发送。模型参数、导入分析范围、上下文详情等控制按需展开。

### 5.5 不伪造透明性

第一版展示真实可验证的信息：使用的模型、分支来源、导入来源、分析档位、错误和状态。不得把生成的解释文本标记为模型真实隐藏思维过程。

## 6. P0：第一版发布必需功能

P0 中任何一项未达到验收标准，第一版不得对外宣称完成。

### F-01 工作区与会话

**用户能力**

- 创建工作区。
- 新建、重命名、删除和打开会话。
- 查看最近会话。
- 关闭并重新打开软件后恢复工作状态。

**边界**

- 第一版只有本地单用户工作区。
- 不做组织、成员、角色、权限和实时协作。
- 项目管理只保留轻量分组，不建设任务管理系统。

**验收标准**

- 用户无需登录即可创建第一段会话。
- 非正常退出后不丢失已经完成保存的节点和消息。
- 删除会话必须二次确认，并说明是否同时删除导入原文件。

### F-02 无限会话画布

**核心对象**

一个会话节点代表一次完整的“用户问题 + AI 回答”，不是一条孤立消息。节点保存模型、时间、父节点、分支类型和来源信息。

**用户能力**

- 平移、缩放、框选或点选节点。
- 拖动节点并保存位置。
- 查看节点之间的父子关系。
- 从任意节点继续提问。
- 让画布自动定位当前节点或适配全部节点。
- 进入聚焦阅读，再返回原画布位置。

**三种分支动作**

- **深入**：沿当前结论继续下钻，继承当前路径的必要上下文。
- **发散**：基于同一背景提出新的相关方向，形成平行探索。
- **换角度**：回到当前节点的上游上下文，用不同假设、角色或方法重新回答。

**边界**

- 第一版只做二维节点与连线。
- 不做自由绘图、白板形状、3D、多人光标、评论和复杂自动布局编辑器。
- 画布不是知识图谱编辑器；它首先服务于会话关系。

**验收标准**

- 创建、拖动、缩放、分支后关系不能错乱。
- 刷新或重启后节点位置、内容和关系能够恢复。
- 200 个普通文本节点下，常规平移和缩放无持续明显卡顿。
- 节点内容不会因缩放、流式输出或按钮状态改变而导致整体布局跳动。

### F-03 基础 Chat

**用户能力**

- 输入多行文本并发送。
- 选择当前使用的模型。
- 查看流式回答。
- 停止生成。
- 对失败回答重试。
- 复制回答内容。
- 从选中节点继续，或在空白画布创建根会话。
- 清楚区分用户内容、AI 内容、系统错误和导入内容。

**上下文规则**

- 从根节点开始时，只发送当前输入和必要系统协议。
- 从节点继续时，默认发送该节点到根节点的有效路径，而不是整个画布。
- 导入会话根据用户选择使用原文轨或接续轨。
- 第一版必须提供“本轮使用了哪些消息”的简单查看入口。

**边界**

- 支持 Markdown、代码块、列表和链接显示。
- 第一版不承诺图片生成、语音、实时视频或复杂多模态编辑。
- 不做 Codex 式终端、仓库修改、测试和部署闭环。

**验收标准**

- 发送后立即出现用户节点或明确的等待状态。
- 流式中断不会破坏已收到内容。
- 超时、限流、余额不足、密钥错误和网络错误必须给出不同提示。
- 重试不会静默产生重复节点。

### F-04 多厂商模型接入

**第一批正式支持**

- OpenAI。
- Anthropic Claude。
- Google Gemini。
- DeepSeek。
- OpenAI-compatible 自定义接口，包括 OpenRouter 类型服务。

**统一能力契约**

- 厂商、模型 ID、Base URL、密钥和可选参数配置。
- 统一的请求、文本增量、完成、停止、错误和用量事件。
- 统一超时、取消、重试和错误归类。
- 每个回答节点记录实际厂商、模型和调用时间。

**第一版商业方式**

- 默认 BYOK，用户使用自己的 API Key。
- 密钥保存到操作系统安全凭据，不写入普通数据库、前端状态或日志。
- 第一版不做平台代付、套餐、额度销售和智能模型路由。

**边界**

- “支持某厂商”必须通过真实 API 契约测试，不能只完成配置表单。
- 厂商独有能力在统一层中允许声明差异，不为追求统一而伪造功能。
- 模型参数默认使用安全推荐值，高级参数放入展开区域。

**验收标准**

- 每个正式支持的厂商至少有一个真实模型完成流式、停止、错误和重试测试。
- 切换模型不会改变已有节点的模型归属。
- 无效密钥不会进入无限重试。
- 日志、崩溃报告和导出文件中不得出现完整 API Key。

### F-05 外部 AI 会话导入器

**导入入口**

- 选择或拖入文件。
- 直接粘贴会话文本。
- 支持 Markdown、TXT、JSON 和 JSONL 通用格式。
- 基于真实导出样本提供 ChatGPT、Claude 和 Codex 专用适配器。

**导入预览**

- 来源平台与文件名。
- 会话、消息、附件和工具记录数量。
- 可恢复、部分恢复和无法恢复的字段。
- 重复项、解析错误和敏感内容提醒。
- 将要在本地处理或发送给模型的范围。

**分析档位**

- **原样继续**：只做确定性格式解析，不执行生成式语义分析。
- **快速识别**：提取当前目标、最后进展、关键约束和下一步。
- **详细分析**：提取完整阶段、决策、分歧、工具调用、成果和未解决问题。

**接续方式**

- 原文轨始终保留。
- 快速或详细分析生成独立接续轨。
- 用户可以查看、修正、删除和重新生成接续轨。
- 分析结论必须能够定位到原始消息。

**边界**

- 第一版不做浏览器账号静默读取、平台爬取和后台自动同步。
- 不承诺导入后复现原平台逐字相同的回答。
- 不自动执行历史会话中的命令、工具调用或外部操作。
- 文件夹、压缩包和增量监控属于后续版本。

**验收标准**

- 官方测试样本的角色、顺序、时间和分支关系不被颠倒。
- 解析失败时保留原文件并允许按纯文本导入。
- 原样继续不会产生模型分析费用。
- 删除分析层后原始会话仍可完整查看。
- 相同文件重复导入时必须提示，不静默复制全部内容。

### F-06 本地数据与恢复

**必须保存**

- 工作区、会话、节点、边和画布位置。
- 消息内容与生成状态。
- 导入来源、原始文件指纹和解析版本。
- 接续轨及其版本。
- 厂商与模型配置，但不包含明文密钥。
- 错误、重试和数据迁移版本。

**边界**

- 第一版本地优先，不强制注册账号。
- 云同步、跨设备同步和多人共享不进入 P0。
- 数据结构必须预留后续工具事件、引用和 Skill 挂载事件，但第一版不要求实现完整编排器。

**验收标准**

- 数据库升级失败时可以回滚或提示恢复，不得直接破坏原数据。
- 用户可以找到本地数据位置并删除自己的数据。
- 原始导入文件与派生分析使用不同记录，不相互覆盖。

### F-07 首次使用与基础体验

**首次进入**

首屏直接提供两个动作：

1. 输入现在想探索的问题。
2. 导入已有 AI 会话。

不显示多页功能教学，不要求先创建复杂项目，也不要求先理解节点、Skill 或上下文协议。

**渐进引导**

- 第一次回答完成后，在节点上自然出现“深入、发散、换角度”。
- 第一次创建分支时，短暂说明三种关系的区别。
- 第一次配置真实模型时解释密钥保存位置和费用归属。
- 第一次导入时解释原文轨与分析层的关系。

**验收标准**

- 新用户在不看文档的情况下，3 分钟内能够完成第一次提问或导入。
- 所有空状态都提供下一步动作。
- 加载、空白、失败、离线和无密钥状态都有明确反馈。

## 7. P1：有余力再做，不阻塞第一版发布

P1 只能在所有 P0 达到验收标准后进入开发：

- 画布全文搜索和节点筛选。
- 会话与画布导出为 MindScape JSON 或 Markdown。
- 节点收藏、高光和轻量标签。
- 两个模型对同一节点生成平行回答并进行人工对比。
- 导入文件夹或 ZIP 导出包。
- 简单 Token、费用和响应耗时显示。
- 键盘快捷键和命令面板。
- 基础无障碍和主题微调。

P1 未完成不得成为推迟第一版上线的理由。

## 8. 明确不进入第一版

以下能力属于长期方向，但第一版禁止自行立项：

- 自动识别并挂载完整 Skill、MCP 和插件体系。
- 通用 AI 工具市场和第三方插件商店。
- 漫游分析配方系统。
- 完整透明推理时间线、结论证据图和专家审计界面。
- 网页搜索、PDF、音视频、OCR、翻译和复杂可视化工具集。
- Synthesis AI 的 Word、PDF、PPT、Notion 全套成果生产。
- Obsidian、Notion、GitHub 和 VS Code 双向同步。
- HyperPhase 截图、录屏、全局捕捉和独立剪贴板。
- 社区、知识图谱市场、分享、Fork 和推荐系统。
- 云同步、团队空间、实时协作和企业权限。
- 平台代付、订阅计费和模型额度销售。
- 自动模型路由、模型评分和智能成本调度。
- 3D 画布、复杂着色器和大型知识图谱渲染。
- 通用终端、代码仓库自主修改、测试、提交和部署。

需要新增以上任何能力，必须先提出范围变更，说明它替换哪个现有 P0、增加多少周期、引入哪些依赖，不能以“顺手做了”为理由进入版本。

## 9. 核心信息架构

```text
Workspace
└── Conversation
    ├── CanvasNode
    │   ├── UserMessage
    │   ├── AssistantMessage
    │   ├── Provider + Model
    │   ├── ParentNode
    │   └── BranchType
    ├── CanvasEdge
    ├── ImportSource
    │   ├── RawTranscript
    │   ├── ParseReport
    │   └── DerivedContinuation
    └── CanvasViewport
```

第一版的产品中心是 `Conversation`，不是文档、任务或知识图谱。后续成果与工具系统围绕这一稳定对象扩展。

## 10. 关键交互规则

### 10.1 选中状态

- 画布始终最多有一个“当前节点”。
- 输入区清楚显示将从哪个节点继续。
- 未选择节点时发送，创建新的根节点。
- 删除当前节点时必须说明是否连带删除后代；默认不静默级联。

### 10.2 上下文继承

- 深入：继承根节点到当前节点的路径。
- 发散：继承背景与关键约束，不默认继承当前结论。
- 换角度：继承当前问题的上游背景，不继承当前回答作为已确认事实。
- 用户可以在发送前查看并移除准备携带的上下文。

### 10.3 模型切换

- 模型选择只影响下一次生成。
- 已有节点永久记录原模型，不因全局配置变化而改写。
- 不支持某项输入能力时必须提前提示，不在发送后静默降级。

### 10.4 导入与分析

- 先展示解析预览，再让用户选择分析档位。
- 分析推荐必须说明收益与预计成本。
- 用户可以跳过分析并立即继续。
- 导入后首先定位最近有效进展，而不是把整段历史铺满画布。

## 11. 非功能质量标准

### 性能

- 冷启动目标：主流近三年 Windows 设备上 3 秒内进入可操作界面。
- 本地会话打开目标：普通工作区 1 秒内出现已有节点。
- 平台自身对首次 Token 的额外处理开销目标：P95 小于 300 毫秒，不含厂商网络与推理时间。
- 200 节点画布必须保持可用；超过推荐规模时提示拆分会话，不静默崩溃。

### 稳定性

- 流式生成、导入和数据库写入均可中断恢复。
- 单个节点或单个导入文件失败不能导致整个工作区不可打开。
- 所有数据库变更具有版本和迁移测试。

### 安全与隐私

- API Key 使用操作系统安全凭据。
- 导入默认本地解析；调用模型前显示发送范围。
- 日志默认脱敏，不记录完整会话正文和密钥。
- 外部导入内容一律作为不可信数据，不自动执行其中的指令。

### 可访问性

- 关键命令可使用键盘完成。
- 图标按钮具有可读名称和提示。
- 文本、按钮和状态不能只依赖颜色区分。
- 1280×720 为桌面最低重点适配尺寸；窄窗口仍需完成基础聊天和配置操作。

## 12. 成功指标

### 北极星指标

**有效继续会话数**：用户在创建或导入会话后，完成至少两轮后续提问或创建一个有效分支的会话数量。

### 第一版核心指标

- 首次价值时间：首次打开到获得第一条 AI 回答或完成一次导入的时间。
- 导入成功率：可解析并进入画布的导入次数 / 总导入次数。
- 导入后继续率：导入后 24 小时内至少继续一轮的会话比例。
- 分支使用率：产生至少一个深入、发散或换角度分支的活跃会话比例。
- 多模型使用率：同一用户在 7 天内使用两个以上模型的比例。
- 会话恢复成功率：重启后能够完整恢复工作区的比例。
- 生成失败率：剔除厂商明确不可用后的平台侧失败比例。

第一版不以注册量、画布节点总数或 Token 消耗作为核心成功指标。这些数字增长不等于用户获得价值。

## 13. 团队并行拆分

### 产品与设计

- 维护范围、流程、状态、交互文案和验收清单。
- 先完成根会话、节点分支、导入预览、模型配置四条关键流程。
- 所有新增设计必须对应 P0 编号。

### 画布前端组

- 负责节点、边、视口、选择、拖拽、分支和聚焦阅读。
- 只依赖稳定的会话图数据契约，不直接处理厂商 API。

### Chat 前端组

- 负责输入、流式渲染、停止、重试、错误状态和模型选择。
- 只消费统一流式事件，不解析厂商原始 SSE。

### 桌面与数据组

- 负责 Tauri、本地数据库、迁移、文件读取、原始导入存储和安全凭据。
- 为前端提供明确命令接口，不让组件直接读写数据库文件。

### 模型网关组

- 负责各厂商适配器、取消、超时、重试、错误归类和用量归一化。
- 建立真实 API 契约测试与脱敏日志。

### 导入与 AI 组

- 负责通用解析、平台专用适配、完整度报告、快速识别和详细分析。
- 建立真实导出样本库和导入回归测试，分析结论必须携带原文位置。

### QA 组

- 建立跨模块端到端用例、损坏文件样本、长会话样本和各厂商错误场景。
- 发布验收以本文件 P0 标准为准，不以“页面已做出来”为完成标准。

## 14. 必须先冻结的跨团队契约

多个团队并行前，先冻结以下接口的 V1 版本：

1. 会话、节点、边和分支类型的数据结构。
2. 统一流式事件：开始、文本增量、完成、停止、错误、用量。
3. Provider 能力声明与错误分类。
4. 导入源、原始消息、解析报告和接续轨结构。
5. 本地数据库迁移与安全凭据接口。
6. 画布前端读取和写入会话图的命令接口。

接口冻结不代表永远不改。任何破坏性修改必须带版本、迁移方案、受影响团队和回滚方式。

## 15. 建议交付阶段

### 阶段 0：契约与样本

- 冻结六项跨团队契约。
- 收集 ChatGPT、Claude、Codex 真实导出样本。
- 建立五家模型测试账号与最小调用样本。
- 完成关键流程原型和状态清单。

**退出条件**：团队不再对“节点是什么、上下文怎么继承、导入后保存什么、流式事件长什么样”存在不同理解。

### 阶段 1：内部 Alpha

- 空白会话、画布、一个模型、通用导入和本地保存贯通。
- 优先完成完整纵向闭环，不追求五家模型同时完成。

**退出条件**：内部成员可以连续使用一周，关键数据不丢失。

### 阶段 2：多模型与专用导入 Beta

- 完成正式支持的模型厂商。
- 完成 ChatGPT、Claude、Codex 专用适配。
- 补齐停止、重试、错误、重复导入和恢复。

**退出条件**：真实旧会话能够导入并继续，各厂商通过契约测试。

### 阶段 3：V1 发布候选

- 完成性能、隐私、崩溃恢复和首次体验验收。
- 清零所有 P0 阻断问题。
- 使用真实用户完成核心场景测试。

**退出条件**：所有 P0 验收项通过，P1 未完成项从发布计划中移除而不是继续拖延。

## 16. V1 发布定义

第一版只有在一个陌生用户能够独立完成以下流程时才算完成：

1. 不登录打开 MindScape。
2. 配置一个真实模型并成功发送消息。
3. 在画布上理解当前会话与分支关系。
4. 从任意节点创建深入、发散或换角度分支。
5. 导入一段真实外部 AI 会话。
6. 理解并选择原样、快速或详细分析。
7. 在导入上下文上继续获得有效回答。
8. 切换另一个模型继续，而不改写已有节点。
9. 关闭并重新打开软件，继续刚才的工作。
10. 清楚知道数据保存在哪里、哪些内容被发送给了模型。

完成页面、组件或接口不等于完成第一版。只有完整用户闭环和数据可靠性同时成立，版本才允许发布。

## 17. 当前需要管理层确认的事项

以下决策不阻塞各组开始准备，但必须在阶段 0 结束前确认：

1. 第一版正式支持的 Windows 最低版本，是否同时承诺 macOS。
2. 第一版是否只采用 BYOK，还是预留少量平台代理体验额度。
3. ChatGPT、Claude、Codex 可稳定获得的真实导出格式与样本。
4. 本地数据库是否默认加密，以及忘记密码后的数据恢复策略。
5. 详细分析允许发送的默认范围和费用提示方式。
6. 第一版内测人数、目标用户构成和发布质量门槛。

这些事项由管理层作最终选择，不交给各开发组分别假设。
