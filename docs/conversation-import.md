# MindScape 外部 AI 会话导入

> 状态：概念设计  
> 最近更新：2026-08-14

## 产品目标

用户不应因为切换 AI 平台而失去已经完成的思考和工作。MindScape 要把 Claude、Codex、ChatGPT 及其他工具中的会话转化为可继续推进的上下文、项目记录和成果，同时完整保留原始资料。

## 核心原则

### 原始记录不可变

导入文件按原样保存并计算内容指纹。解析、总结、纠错、标签和关系都作为派生层存在，不能覆盖原始会话。

### 统一但不抹平差异

所有平台映射到统一会话图，但保留平台专有字段。Codex 的命令、文件修改和工具结果，与普通文本回答有不同语义；Claude 的附件或分支也不应被压成纯文本。

### 导入不等于全量注入

长会话先被分段、索引和理解。每次调用只编译与当前任务相关的部分，并附上来源位置。用户可以查看“这次 AI 实际读了哪些历史内容”。

默认导入也不等于全量语义分析。系统先做格式解析、索引和低成本定向扫描，再依据目标相关度与决策价值决定哪些片段值得深入。用户明确启用漫游分析时，才按照选定配方对整个范围进行广域分析。

### 默认本地与安全

解析、格式识别、索引和基础搜索默认在本地完成。需要模型进行语义提炼时，明确显示将发送的范围。导入内容中的命令、提示词和工具调用全部视为历史数据，不会自动执行。

### 继续工作与分析深度分离

“继续这次工作”是用户目标，“是否分析”是处理策略，两者不能绑定。用户可以原样继续，也可以在继续前进行快速或详细分析。

导入后提供四个清晰档位：

| 档位 | 系统行为 | 模型消耗 | 适用情况 |
| --- | --- | --- | --- |
| 原样继续 | 仅解析格式和保留原文；可携带全部原文或最近消息 | 无前置分析成本；后续成本取决于携带范围 | 短会话、目标明确、只想接着聊 |
| 快速识别 | 提取当前目标、最后进展、关键约束和下一步，形成可复用上下文包 | 低前置成本；通常降低后续每轮成本 | 大多数正常续接 |
| 详细分析 | 分析完整脉络、决策、分歧、工具调用、成果和遗漏 | 中到高 | 长会话、复杂项目、需要可靠交接 |
| 漫游分析 | 按用户配方广域扫描并寻找意外线索 | 用户自定 | 资料考古、复盘和系统研究 |

“不分析”指不进行语义提炼，不代表无法查看或继续会话。格式解析、完整性检查和安全隔离仍作为本地基础处理执行。

不分析存在一个明确取舍：

- 携带全部原文：信息最完整，但长会话会在后续每轮重复消耗大量上下文。
- 只携带最近消息：成本更低，但可能遗漏早期目标、约束和决策。

快速识别会产生一次前置成本，但生成的上下文包可在后续多轮复用。因此成本展示必须区分“本次分析成本”和“预计后续会话成本”，不能简单把不分析标成最省。

系统可以根据会话长度、分支数量、工具调用、主题变化和当前问题推荐一个档位，但推荐必须同时展示：预计收益、读取范围、Token / 时间成本以及哪些内容会发送给模型。用户选择始终优先。

### 保真接续与分析接手

导入后能否恢复导入前的表现，取决于是否完整迁移了以下状态：

1. **可见会话**：用户与 AI 的消息、顺序、分支、附件和引用。
2. **行为上下文**：原平台的系统提示、项目指令、个人记忆、模型参数和隐藏摘要。
3. **执行上下文**：本地文件、Git 状态、工作目录、工具定义、工具结果、运行中的任务和外部服务状态。
4. **模型运行时**：同一模型版本、服务端策略、上下文编排方式和采样状态。

普通导出文件通常只能完整提供第一层，并提供部分第三层；第二层和第四层往往由原平台控制，无法从导出记录中获得。因此，即使使用同一模型，也只能追求语义与工作连续性，不能承诺再次得到完全相同的输出。

MindScape 在导入后生成“接续完整度报告”，明确显示：

```text
已恢复：42 轮消息、3 个代码片段、1 个附件、7 次工具结果
部分恢复：文件修改记录（缺少当时工作区快照）
无法恢复：原平台系统提示、隐藏记忆、精确模型版本、运行中进程
建议：连接 NeoCarry 仓库并选择对应 Git 提交，再继续开发任务
```

### 双轨接续

推荐默认采用“双轨接续”，而不是在原文与分析之间二选一：

- **原文轨**：不可变地保存完整会话、附件、工具记录和来源，作为最高保真证据。
- **接续轨**：根据所选分析档位生成目标、约束、决策、进度和未解决问题等可复用上下文包。

主 AI 先获得接续轨中的最小工作状态，并可通过检索随时回到原文轨获取关键片段。分析错误时可以修正或删除接续轨，不影响原始会话。

若用户选择完全不分析，系统只使用原文轨；若用户换用不同 AI、导入超长会话或原平台状态缺失，分析接续轨的价值通常更大。

## 导入入口

### 第一阶段

- 拖入或选择会话文件。
- 选择包含导出记录的文件夹或压缩包。
- 粘贴 Markdown、JSON、JSONL、HTML 或纯文本会话。
- 使用通用格式导入未知平台内容。

### 后续阶段

- 为常见平台提供官方导出包适配器。
- 浏览器辅助捕捉当前会话，导入前预览范围。
- 经用户授权的 API 或连接器同步。
- 监视本地会话目录并增量导入。

首期不依赖绕过平台限制的网页抓取，也不静默读取浏览器账号数据。

## 统一会话图

建议至少包含以下对象：

```text
ImportSource
Conversation
Branch
Turn
ContentBlock
Attachment
ToolCall
ToolResult
Artifact
Citation
Participant
ImportRevision
DerivedInsight
```

关键字段包括：

- 原平台与原会话标识
- 消息角色、模型和时间
- 父消息与分支关系
- 文本、代码、图片、文件等内容块
- 工具名称、输入、输出和执行状态
- 涉及的文件及差异记录
- 引用、链接和附件
- 原始文件中的定位信息
- 导入版本和去重指纹

## 导入处理流程

```text
选择数据
→ 本地识别格式与预览范围
→ 保存原始文件
→ 解析为统一会话图
→ 校验完整性与重复项
→ 用户选择处理目标与分析档位
→ 按所选档位原样续接或进行语义分析
→ 生成续接上下文或分析报告
→ 进入项目或新会话
```

迁移报告应明确：解析了多少会话和消息、哪些附件缺失、哪些字段无法还原、是否发现重复记录，以及哪些内容可能包含敏感数据。

## 用户可以如何处理

导入后不立刻替用户决定用途，而是提供几个清楚的动作：

- **继续这次会话**：构建精确的续接上下文并开始新一轮工作。
- **并入项目**：关联已有项目，提取决策、任务、资料和成果。
- **提炼成果**：生成文档、方案、代码变化摘要或阶段报告。
- **重建脉络**：识别主题阶段、分支、转折和否决原因。
- **比较会话**：关联多个模型对同一问题的回答与结论。
- **归档检索**：只建立本地索引，不立即调用模型分析。
- **漫游分析**：按照选定的分析配方完整扫描导入范围，发现跨主题线索、决策、风险、工具行为与潜在问题。

这些动作与分析档位可以组合。例如“并入项目 + 快速识别”“继续会话 + 不分析”或“提炼成果 + 详细分析”。

## 如何建立分析信任

MindScape 不应声称“分析一定比不分析好”。短会话和目标明确的任务中，原样继续可能更快、更忠实。产品需要证明的是：当分析值得进行时，它能产生可验证的增量价值。

每次推荐分析时展示一张简短收益预览：

```text
推荐：快速识别
原因：会话包含 3 次目标变化，最近结论分散在 18 条消息中。
预计获得：当前目标、已确认约束、最后进展、下一步。
预计成本：一次性约 8k 输入 Token，10-20 秒；预计后续每轮减少约 20k 历史上下文。
将发送：纯文本消息；不包含附件和工具输出。
```

分析完成后展示“分析带来了什么”：

- 找到了哪些原样继续容易遗漏的约束或决策。
- 压缩了多少历史上下文。
- 预计在后续多少轮内抵消本次分析成本。
- 每项结论对应哪条原始消息。
- 哪些部分没有分析或无法确认。
- 用户可以一键撤销分析层并切回原始会话。

用户对分析的信任应来自可预览、可引用、可比较和可撤销，而不是默认开启或宣传承诺。

## 续接上下文

为了继续旧会话，系统生成的不是单一摘要，而是一组可追溯的上下文层：

- 当前目标与任务阶段
- 已确认决策及依据
- 用户偏好和明确约束
- 已完成工作与现有成果
- 未解决问题和下一步
- 关键原文片段
- 相关附件、文件和代码状态

任何摘要都可点击返回原始轮次。用户可以纠正错误提炼，并选择哪些内容允许进入新会话。

接续目标不是复刻原模型下一句话的字面输出，而是尽量恢复：

- 对目标和约束的理解。
- 已确认与被否决的决策。
- 当前工作进度和外部状态。
- 原有证据、附件和关键工具结果。
- 在不重复解释背景的情况下继续完成任务的能力。

如果用户确实需要复现实验结果，必须额外保存模型标识、参数、系统指令、完整上下文、工具版本和环境快照；即使如此，非确定性模型也不保证逐字一致。

## 多来源合并

同一个项目可能同时存在于 Claude、Codex 和其他平台。MindScape 应通过项目标识、文件路径、仓库信息、主题和用户确认建立关联，而不是仅按文本相似度自动合并。

合并时需要保留：

- 每条事实和决策的来源。
- 不同模型之间的冲突意见。
- 同一任务的多个版本。
- 已被否决方案及原因。
- 哪些结论由用户最终确认。

系统可以建议重复和冲突，但不应静默删除历史。

## MVP 范围

第一版建议支持：

1. 通用 Markdown、JSON、JSONL 和纯文本导入。
2. Claude 与 Codex 两个专用适配器。
3. 原始文件保留和统一会话图转换。
4. 会话预览、基础搜索和来源回溯。
5. 目标、决策、任务、成果、未解决问题的提取。
6. “继续会话”与“并入项目”两个核心动作。
7. 导入范围、模型发送范围和解析异常报告。
8. 快速识别、智能分析和漫游分析三种分析深度入口，但默认只展示推荐操作。
9. 原样继续，不执行任何生成式语义分析。

具体适配格式需要基于用户实际可取得的导出样本验证，不能只凭平台名称假设字段结构。

## 待决策问题

- 原始导入文件的存储、加密和清理策略。
- 附件与会话文件分离时的路径修复方式。
- Codex 工具调用和代码差异采用何种统一表示。
- 多次导入同一会话时的增量更新与冲突处理。
- 用户是否可以导出 MindScape 的开放会话格式。
- 本地分析与云端模型分析的默认边界。
- 接续完整度如何评分，以及哪些缺失项必须阻止“高保真”标识。
