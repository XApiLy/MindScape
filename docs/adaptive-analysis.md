# MindScape 自适应分析引擎

> 状态：概念设计  
> 最近更新：2026-08-13

## 目标

自适应分析引擎解决两个相互冲突的问题：

- 简单用户希望导入或发送内容后，系统直接指出问题和需求。
- 高级用户希望检查完整意图、推理依据、工具调用、文件变化和所有潜在线索。

MindScape 不为此制造两套产品。底层使用同一个分层分析管线，界面通过渐进披露和用户偏好控制信息密度。

## 两个核心指标

### 目标相关度（Relevance）

衡量某段信息与当前目标、子任务和预期成果的直接关系。

判断依据可以包括：

- 是否回答当前问题。
- 是否构成必要背景或约束。
- 是否与正在使用的项目、文件或对象直接关联。
- 是否影响用户明确要求的成果。
- 是否只是相似主题但不影响当前工作。

### 决策价值（Decision Value）

衡量继续深入分析后，是否可能改变用户或系统接下来的行动。

可能具有高决策价值的内容包括：

- 能推翻或修正当前结论。
- 暴露关键风险、矛盾或遗漏。
- 改变下一步任务顺序。
- 改变应该挂载的 Skill、MCP 或工具。
- 揭示需要用户确认的重要歧义。
- 能显著提高最终成果质量。

Token、费用、延迟和隐私不是第三、第四个价值指标，而是分析预算约束。

## 分析门控

可以用二维判断理解默认策略：

| 目标相关度 | 决策价值 | 默认处理 |
| --- | --- | --- |
| 高 | 高 | 深入分析，必要时调用能力或请求确认 |
| 高 | 低 | 直接引用、压缩或归档，不重复深挖 |
| 低 | 高 | 标记为潜在线索，说明可能影响，等待确认或漫游分析 |
| 低 | 低 | 仅保留索引，不消耗模型分析预算 |

实际系统可以使用连续评分，但界面不必向普通用户展示复杂数值。用户只需看到“为什么分析了这部分”或“为什么跳过了这部分”。

## 分层分析管线

### 第 0 层：结构解析

本地完成格式识别、消息切分、附件关联、时间线、工具调用和文件路径提取。尽量不使用生成式模型。

### 第 1 层：快速定向扫描

低成本识别：

- 用户或资料主要在做什么。
- 当前最明确的问题和需求是什么。
- 是否存在需要立即处理的高价值矛盾或风险。
- 哪些片段可能值得深入。

默认结果应非常简洁，例如：

```text
识别：这是一次产品路线讨论。
关键问题：目标用户尚未确定，导致功能优先级无法收敛。
建议：先分析 3 处用户定位分歧；其余内容暂不深挖。
```

### 第 2 层：目标分析

围绕当前问题深入相关片段，提取证据、决策、约束、工具行为和可执行下一步。只扩展高相关、高决策价值内容。

### 第 3 层：广域分析

跨主题、跨分支和跨会话寻找关系、矛盾、模式与潜在线索。默认不自动进入，本层主要由漫游分析或高级用户明确要求触发。

## 用户体验层级

用户不必先选择复杂模式。默认由系统推荐合适深度，并提供一个可展开状态：

```text
已完成快速识别 · 深入分析了 3 个关键片段 · 跳过 47 个低价值片段
```

用户可以选择：

- **保持简洁**：只呈现核心问题、需求和下一步。
- **查看依据**：展开引用、评分理由和分析范围。
- **深入这里**：对选中问题增加预算。
- **查看全部过程**：展示意图变化、能力装载和工具调用。
- **开始漫游**：使用选定配方进行广域分析。

偏好可设置为全局、项目、会话或单次覆盖。系统可以学习展示偏好，但不能因此永久隐藏高风险信息。

### 推荐不是替用户决定

分析深度由用户最终选择。系统推荐时必须给出原因、范围、预计收益、Token / 费用 / 时间估算和数据发送边界。

用户可以选择：

- **不分析**：保留原始内容，直接继续。
- **快速识别**：只提取续接所需的最低信息。
- **详细分析**：理解完整脉络和工具行为。
- **漫游分析**：按配方做广域探索。

不要使用默认勾选、模糊按钮或恐惧提示诱导分析。系统应允许用户将偏好设为“总是询问”“智能推荐但不自动执行”或“在预算内自动快速识别”。

### 分析价值证明

产品目标不是让用户相信分析在所有情况下都更好，因为这个命题不成立。目标是让用户相信：

> 当系统建议分析时，它能说明为什么值得，并让结果接受验证。

分析前提供收益预览，分析后提供增量报告。可以将“原样上下文”和“分析后的上下文包”并排比较，展示：

- 保留了哪些关键事实和约束。
- 发现了哪些冲突或遗漏。
- 减少了多少无关上下文。
- 消耗了多少 Token 和时间。
- 前置分析成本与预计后续每轮上下文成本。
- 有哪些分析结果仍属推断。

只有被用户采用、影响下一步或减少上下文成本的发现，才能计入分析收益。

## 漫游分析

### 定义

漫游分析是一种弱目标或无单一目标的广域理解方式。它按照预先定义的分析配方遍历指定资料，既寻找已知维度，也允许记录意外但高价值的发现。

### 标准配方

默认配方可以包含：

1. 主题、目标和阶段变化。
2. 关键观点及其证据。
3. 已确认、暂定和被否决的决策。
4. 假设、约束、风险、矛盾和盲点。
5. 待办、负责人、进度和未解决问题。
6. 工具调用、文件变化、错误和执行结果。
7. 已产生成果及其成熟度。
8. 跨会话重复、冲突和演进关系。
9. 值得进一步探索的新问题。

### 可配置项

- 分析范围：单个片段、会话、项目或资料集合。
- 关注维度：选择或新增分析问题。
- 深度：快速、标准、彻底或自定义。
- 预算：Token、费用、时间和并发限制。
- 隐私：仅本地、允许发送的内容类型和模型范围。
- 证据要求：是否每个结论必须附原文引用。
- 停止条件：预算耗尽、没有新增发现、达到覆盖率或用户停止。
- 输出：报告、知识图、问题列表、决策表或项目上下文包。

### 运行结果

漫游分析不应生成一份无法操作的超长摘要。结果按以下结构沉淀：

- 发现卡片
- 证据引用
- 冲突与待确认项
- 可执行动作
- 可加入项目的决策和任务
- 可继续深挖的探索入口
- 本次覆盖范围和未分析范围

用户可以保存配方，例如“代码项目考古”“产品讨论复盘”“学习资料整理”，之后对不同数据重复使用。

## 预算控制

每次分析建立预算信封：

```text
允许的模型与本地能力
最大 Token / 费用 / 时间
允许发送的数据范围
目标覆盖范围
证据要求
停止条件
```

系统优先把预算分配给目标相关度与决策价值都高的片段。预算不足时明确显示未分析范围，而不是假装已经完整理解。

## MVP

第一版实现：

1. 本地结构解析。
2. 快速定向扫描。
3. 目标相关度和决策价值的粗粒度判断。
4. 自动推荐少量深入片段。
5. 简洁结果与高级详情的渐进披露。
6. 一个标准漫游分析配方。
7. 用户可设置范围、深度和 Token 上限。
8. 所有发现回溯到原始内容。

第一版不追求精确的覆盖率数学模型，也不自动对所有导入数据运行漫游分析。

## 评估指标

- 深入分析片段中被用户认为有用的比例。
- 被跳过内容中后来被用户手动要求分析的比例。
- 相比全量分析节省的 Token、时间和费用。
- 用户纠正相关度或决策价值判断的比例。
- 简洁用户完成任务时展开高级详情的频率。
- 漫游分析产生并被用户采纳的新发现数量。
