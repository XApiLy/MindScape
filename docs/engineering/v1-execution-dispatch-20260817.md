## 1. 本轮只交付一个结果

本轮目标不是继续完善五个独立模块，而是交付第一条可真实使用、可恢复的 Chat 纵向闭环：

```text
配置一个真实 Provider 与模型
→ 从根节点或选中节点发送问题
→ 后端冻结 ContextSnapshot 并统一创建运行
→ 真实模型流式回答
→ 用户可以真正停止
→ 终态、部分内容、模型和节点一致落库
→ 强制退出并重启后状态明确且会话可继续
→ 画布与阅读视图展示同一份领域事实
```

本轮不进入导入器、完整多厂商、Skill / MCP、DeepSeek Harness、AI IDE、本地工作 Agent、视觉重构和 P1 功能。发现相关需求只登记，不进入当前 WIP。

## 2. 当前工程事实

截至派单前，正式工程已经具备会话图、冻结上下文、SQLite schema v4、模型运行事件存储、模拟 Provider、Tauri 流式 Channel、取消命令、Chat reducer 和画布投影。

当前三个发布阻断缺口是：

1. Provider 注册表只有 Mock，设置页和模型选择器也只有模拟项。
2. 前端仍负责 `append_turn → run_model → complete_turn` 的跨层编排；进程在终态与 `complete_turn` 之间退出时，节点与 ModelRun 可能不一致。
3. 没有启动恢复扫描，未完成运行重启后的查询与修复语义尚未落地。

外部会话导入器当前尚未实现，但不得在上述三项完成前抢占五人主 WIP。

## 3. 管理层冻结的执行选择

- V1 Alpha 先支持 Windows，其他桌面平台不阻塞本轮。
- V1 继续采用 BYOK，Key 只进入操作系统安全凭据。
- 首个真实通路采用 OpenAI-compatible 协议底座，并用 DeepSeek 作为第一验收端点；完成真实契约测试后才能标记“支持”。
- 后续顺序为 OpenAI / OpenRouter 兼容配置、Anthropic、Gemini，不允许五家同时开工。
- Harness 不进入 V1 当前开发，只保留架构提案；没有准确仓库、许可证和对照实验前不建立适配器。
- 当前范围是 Chat AI。任何终端、仓库修改、测试、提交、部署和桌面控制能力均拒绝进入本轮。

## 5. 员工02：后端运行协调与崩溃恢复

### 本轮主任务

完成 `CORE-014～015`、`DATA-014～015` 的最小可交付切片，把运行生命周期从 React 收回应用层，并实现启动恢复。

### 必须交付

- 提供一个后端应用命令完成：校验输入、创建 pending Node、冻结上下文、创建 ModelRun、调用 Provider、持久化事件、根据终态更新 Node。
- completed、cancelled、failed 的节点与运行状态必须在后端保持一致；前端关闭事件通道不能伪造完成。
- 启动时扫描残留 pending / streaming 运行，将不可继续的运行标记为明确 interrupted 或契约规定的等价状态，并保留已经持久化的部分输出。
- 暴露重启后的运行查询投影，供员工04恢复 UI，不能要求前端读取数据库或猜测状态。
- 增加“终态前退出”“终态事件已落库但节点未完成”“重复终态事件”和“事件通道关闭”的恢复测试。

### 本轮不得做

- 不顺带建设导入表、删除系统或完整备份界面。
- 不让 SQLite 状态反向定义领域状态机。
- 不把 Provider 网络逻辑写进数据层。

### 验收与评审

- 直接评审人：员工01；Provider 边界由员工05共同评审。
- 退出条件：人为在流式中、终态前后强制关闭应用，重启后均无永久 pending 节点，已完成数据不丢失。
- 建议分支：`feat/CORE-014-run-coordinator`，恢复测试另开 `fix/DATA-015-interrupted-run-recovery`。

## 6. 员工03：画布运行一致性与视口持久化

### 本轮主任务

完成 `CAN-012`、`CAN-014`，并建立 `CAN-019` 的首个可重复基准。

### 必须交付

- 切换到员工02的运行查询投影；临时流式节点与正式节点只能通过稳定 `nodeId` 就地合并，不能出现重复卡片。
- 完成按会话保存和读取 `x、y、zoom`，重启后恢复，不再只保存在 React 内存。
- 流式文本增长时不触发全图持续重排；停止、失败、中断和完成状态在画布与阅读视图一致。
- 建立 200 节点固定样本与基准记录，至少记录初次投影、平移、缩放、选中和流式更新的可观察结果。
- 增加视口重启恢复、临时节点合并和终态切换回归测试。

### 本轮不得做

- 不做小地图、视觉改版、自由白板或复杂动画。
- 不在画布组件中决定运行终态或拼接上下文。
- 不使用坐标推导分支关系。

### 验收与评审

- 直接评审人：员工01 + 员工04；持久化接口由员工02确认。
- 退出条件：同一会话在发送、停止、失败、刷新和重启后没有重复节点、错边或视口丢失。
- 建议分支：`feat/CAN-014-persist-canvas-viewport`。

## 7. 员工04：真实模型配置与 Chat 闭环

### 本轮主任务

## 8. 员工05：首个真实 Provider

### 本轮主任务

完成 `PROV-005～008`、`PROV-013～017` 的首个真实垂直切片：OpenAI-compatible 底座 + DeepSeek 真实验收。

## 11. Alpha 统一验收脚本

必须在真实 Tauri Windows 应用中完成，保留脱敏录屏或截图、测试输出和对应 PR：

1. 新用户创建本地会话并配置 DeepSeek 凭据。
2. 发送根问题，看到真实流式回答，节点记录真实 Provider 与模型。
3. 从该节点分别创建继续、深入、发散或换角度中的至少两类分支，并查看实际 ContextSnapshot。
4. 在第二次回答中途停止，部分内容保留，状态不是 completed。
5. 再次运行并在流式中强制关闭应用；重启后没有永久 pending，历史完成节点不损坏。
6. 使用无效 Key，显示鉴权解决方案，不自动无限重试。
7. 断网或模拟超时，显示网络 / 超时错误，不生成伪 assistant 回答。
8. 重启后会话、节点、边、模型归属、位置和视口恢复。
9. 搜索数据库、日志和崩溃信息，不出现完整 API Key。
10. 运行全部适用前端、Rust、PEC 和仓库治理检查。

任一第 2、4、5、6、8、9 项失败，本轮结论为 No-Go。
