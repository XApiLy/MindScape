# M1 创始人强制退出验收手册

> 用途：协助员工02完成M1恢复门禁  
> 当前有效程序以 `artifacts/acceptance/LATEST.txt` 为准  
> 当前操作版本：`20260819-150500-prov-013-mock-default-fix-0cb1c0053b5a-dirty`

## 创始人只需要做什么

创始人不需要查数据库、不需要改代码、不需要传API Key。只需要在同一个正式Release程序中完成两次强制退出，并把操作时间和窗口现象告诉员工02。

不要启动Vite开发服务器，不要打开`target/`里的程序，不要使用旧Build ID。当前窗口若仍显示MindScape且进程路径为`artifacts/acceptance/versions/`，可以继续使用。

## 测试前确认

1. 打开当前正式程序：从 `artifacts/acceptance/LATEST.txt` 读取完整路径。
2. 设置页中的Key只通过系统凭据入口配置，不要把Key发送到聊天、截图或PEC。
3. 选择真实DeepSeek模型，不要选择Mock。
4. 新建一个测试会话，记录当前Build ID。

## DATA-015-A1：收到部分内容后强制退出

1. 在真实DeepSeek模型下发送一个要求长回答的问题，例如要求分多个章节详细分析一个主题。
2. 看到回答已经出现多段文字后，不要点击停止，也不要点击窗口右上角关闭。
3. 打开任务管理器：`Ctrl + Shift + Esc` →“详细信息”。
4. 找到路径对应当前Build ID的`mindscape-desktop.exe`，确认PID后点击“结束任务”。当前这次窗口的PID是`13296`，重启后PID会变化，不能固定使用。
5. 等待3秒，再从同一个Build ID重新打开程序。
6. 打开刚才的测试会话，等待启动恢复完成，截图记录：运行是否显示失败/已中断、部分内容是否保留、是否出现重复卡片。

通过条件：运行变为`failed + application_interrupted`；已收到的部分内容保留；没有永久`pending/streaming`；没有重复Node/Run；历史完成节点不变；画布和阅读视图只显示一个稳定节点。

## DATA-015-A2：首Token前强制退出

1. 在同一个正式Release中再新建一个测试会话。
2. 发送问题后，看到界面进入“正在准备”或“正在生成”但还没有任何助手文字时，立即按上面的任务管理器步骤结束当前Build ID对应的进程。
3. 重新打开同一个Build ID，进入该测试会话并等待恢复完成。
4. 截图记录是否形成明确失败/中断状态，是否出现空的重复节点或永久等待。

如果回答已经出现文字，说明没有抓到首Token前窗口；该次不算A2，通过新会话重做，不要把A1结果冒充A2。

## 结束后发给员工02

只发送以下信息，不发送Key或完整回答：

```text
Case ID：DATA-015-A1 或 DATA-015-A2
Build ID：<来自 artifacts/acceptance/LATEST.txt>
强退时间：<北京时间>
强退前：已出现部分文字 / 尚未出现文字
重启后：窗口状态、是否保留内容、是否重复卡片
截图：<脱敏截图路径>
```

员工02随后负责只读SQLite聚合、事件终态、Node/Run唯一性和启动恢复证据。创始人不需要为了配合员工06创建视觉引用；员工06是否参与由创始人另行直接决定。

## 不要做的事

- 不要用正常关闭代替“结束任务”。
- 不要同时打开两个不同Build ID。
- 不要重建`target-fixed`等临时目录。
- 不要重复执行已经通过的PROV-013取消测试，除非员工02明确需要“取消后重启”补充证据。
- 不要把数据库文件、API Key或完整会话正文发给任何人。
