## 1. M2 为什么重新制定

原路线把 M2 定义为“会话导入 Alpha”，但 M1 Go 后已经确认，MindScape 的核心差异不只是把文件带进来，而是：

```text
会话可以导入
→ 模型运行可控
→ 会话内容实体化
→ Markdown 可读知识层
→ 讨论日志可追溯
→ 分支隔离上下文与记忆
→ 本地检索为当前问题提供精准证据
```

如果直接先做平台专用导入，仍然会把导入内容塞回长聊天，无法解决上下文膨胀、记忆污染和跨会话复用问题。因此 M2 先做通用导入的原文保真接入，验证“导入 → 知识内核 → 聚焦连续性”的闭环；M3 再扩展到跨平台专用导入和接续分析。

M1 已 Go。本 M2 不回改 M1 的运行终态、取消、恢复和 Provider 错误语义，只以加法方式扩展运行档案、知识实体、Markdown 投影、日志和 FocusFrame。

## 2. M2 唯一交付结果

用户可以完成以下闭环：

```text
进行 5～10 轮项目讨论，或导入一段 Markdown / JSONL 会话
→ 创建主线讨论日志和导入来源
→ 抽取少量目标 / 决策 / 约束 / 问题实体
→ 用户确认其中的有效事实
→ 生成可被 Obsidian 打开的 Markdown Vault
→ 从主线创建一个局部任务分支
→ 任务分支只继承必要事实，不污染主线记忆
→ 在新 FocusFrame 中提问
→ 通过全文 + 向量 + 关系证据检索
→ 生成带来源的回答
→ 将分支成果作为候选回流，等待用户确认
```

## 3. M2 范围

### 3.1 模型运行控制

- 每次运行生成可查看、可回放的 `Effective Run Profile`。
- 选择 Provider、模型、思考模式、思考预算、输出预算、上下文策略和工具权限。
- Provider 能力目录声明 reasoning、工具、结构化输出、上下文窗口和参数支持情况。
- Provider 不支持的参数发送前明确提示，不静默降级或切换模型。
- `reasoning_content`、可见正文、工具事件和用量事件分开记录。
- 旧运行的实际模型和参数不能被后续设置回写。

### 3.2 通用会话导入

- 支持文件选择、拖放和粘贴。
- 首批支持 Markdown、JSONL 和 TXT 退化导入；JSON 可作为结构化通用格式接入，但不要求恢复平台专有字段。
- 原文件不可变保存、内容指纹、重复检测、编码和大小预检。
- 解析角色、顺序、时间、分支提示、代码块、附件引用和未知内容块；无法识别的字段保留为扩展或原文块。
- 导入预览显示来源、消息数量、可恢复字段、警告和即将进入上下文的范围。
- 导入结果进入原文轨和会话图入口；用户可以选择原样继续，不调用生成式分析。
- 导入的高价值 Goal / Decision / Constraint / Question 只能在用户明确选择“沉淀知识”或系统提出候选后进入实体化流程。
- 导入中断、重复导入、损坏文件和重启恢复必须有明确状态。

### 3.3 FocusFrame 与分支记忆

- 创建、切换、关闭和恢复 FocusFrame。
- 支持继续当前问题、聚焦新问题、从节点分支和原样续接四种上下文策略。
- 分支拥有 `inherit`、`local`、`exclude`、`promote` 四类记忆集合。
- 主线、探索分支、任务分支和复盘分支拥有可解释的作用域。
- 任务分支的临时推断和错误尝试不自动进入主线 RAG。
- 分支完成后生成回流候选，用户确认后才写入主线或项目知识。

### 3.4 Markdown 知识层与讨论日志

- 生成标准 Markdown 知识目录，可直接作为 Obsidian Vault 打开。
- 使用稳定实体 ID、YAML frontmatter、EvidenceRef 和 Wikilink。
- 生成项目、会话、分支、决策、约束、问题、来源和成果页面。
- 记录每次重要讨论的可读日志；原始消息仍由事件和原文层保留。
- Markdown 编辑被识别为新修订，重新索引，不静默覆盖历史。
- 支持 Markdown 知识导出和本地重新索引；不承诺完整 Obsidian 双向同步。

### 3.5 有限实体化

M2 只做可证明有价值的实体，不做任意知识图谱：

- `Goal`
- `Decision`
- `Constraint`
- `Question / Gap`
- `Source`
- `Project`
- `Topic`

实体状态固定为 `candidate`、`inferred`、`confirmed`、`rejected`、`superseded`、`stale`。模型只能提出候选；用户确认或确定性规则不能与用户事实冲突时，才能进入高可信层。

### 3.6 本地混合检索

- SQLite 结构化实体、关系、版本和证据为事实源。
- SQLite FTS5 或等价全文索引支持名称、关键词和精确短语。
- 建立向量索引适配器，至少完成一个真实本地向量检索路径。
- LanceDB 作为目标实现候选；若 Rust Native 集成影响构建稳定性，必须先通过技术评审选择等价可重建实现，不得把未落地的目标架构写成已完成。
- 检索结合全文、向量、关系邻居、作用域、确认状态、来源权威和新鲜度。
- Context Compiler 根据 FocusFrame、预算和权限生成冻结上下文。
- 检索结果必须提供来源、命中原因和排除项。

### 3.7 Markdown 原生阅读与字体偏好

M2 同时交付 AI 输出和导入 Markdown 的安全阅读呈现。原始 Markdown 仍是不可变事实，渲染 AST、HTML/DOM、纯文本复制和字体偏好均属于可重建表现层；不得把渲染结果写回原文，也不得让阅读设置进入 ModelRun、FocusFrame、实体或 RAG。

- Chat 回答、聚焦阅读器、导入预览和 Markdown 知识页使用同一安全 renderer。
- 首批支持标题、段落、强调、列表、引用、代码块、表格、链接和安全自动链接；默认禁用原始 HTML、脚本、任意 iframe、远程图片主动加载和自动执行命令/工具调用。
- 流式正文使用 raw stream 与 reveal queue 分离，Markdown 按小批次增量解析；用户上滑后不强制滚动，终态必须 flush。
- 阅读字体、字号、行高和阅读宽度可调并本地持久化；优先支持系统/内置安全字体栈，M2 可导入 TTF/OTF/WOFF2 到受控字体目录并提供回退。
- 画布节点保持轻量摘要，不因完整 Markdown 重排破坏 200 节点性能；聚焦阅读器提供完整结构化阅读。
- 复制和导出明确区分渲染文本、原始 Markdown 和代码块；任何解析失败都保留原文并提供可读回退。

详细交互、字体范围、渲染安全和验收矩阵见 [M2 Markdown 原生阅读与字体偏好规格](../design/visual-and-interaction/05-markdown-reading-and-typography-m2.md)。

- 不做新的视觉生产重构；员工06视觉工作由创始人直接安排。

## 5. 跨团队契约

### ARC-M2-001：Effective Run Profile

至少包含：

```text
providerId
modelId
reasoningMode / reasoningBudget
generationParameters
contextPolicy
allowedCapabilities
toolPermission
budgetEnvelope
valueOrigins
capabilitySnapshot
```

每次 ModelRun 保存不可变副本。

### ARC-M2-002：FocusFrame

```text
id
conversationId
parentNodeId
objective
memoryScope
includeRefs
excludeRefs
memoryVersion
createdAt
```

### ARC-M2-003：KnowledgeEntity / Relation / EvidenceRef

实体、关系和证据都必须带稳定 ID、作用域、状态、版本、来源和生成器。任何实体删除、否决或过期都必须影响后续检索。

### ARC-M2-004：Markdown Projection

Markdown 文件必须能从实体和日志重建；文件名变化不能改变稳定 ID；用户编辑通过修订事件进入索引；原始来源不可被 Markdown 派生内容覆盖。

## 7. M2 验收门禁

### 硬性通过条件

1. Markdown、JSONL 和 TXT 退化样本可以导入；原文、角色、顺序、时间、代码块和未知内容不丢失。
2. 损坏、重复、超大和中断导入都有明确报告，失败不会破坏已有工作区。
3. 导入会话能进入会话图，来源可见，用户可以原样继续且不产生生成式分析费用。
4. 同一会话能创建主线和任务分支，任务分支不继承被排除的主线历史。
5. 分支可恢复、可切换、可查看日志，主线和分支实体作用域不混淆。
6. 用户确认的 Goal / Decision / Constraint 能写入 SQLite 和 Markdown，并带 EvidenceRef。
7. 用户编辑 Markdown 后，系统产生新修订，重新索引且不覆盖旧版本。
8. 新 FocusFrame 能通过全文 + 向量 + 关系检索命中确认事实，并显示来源和排除项。
9. 否决、过期或删除的实体不会继续作为有效知识被召回。
10. 模型、思考模式、预算和上下文策略在每次 ModelRun 中可见且不可回写。
11. reasoning 内容不会替代正文，也不会造成空正文成功；M1 终态、取消和恢复回归不退化。
12. 生成的 Markdown Vault 能被 Obsidian 直接打开，实体链接和日志可读。
13. 完整验收使用同一个无开发服务器 Tauri Release Build，证据、哈希和路径符合统一发布规则。

### No-Go 条件

- 任何主线 / 任务分支记忆污染。
- 原文被 Markdown、摘要、实体或向量索引覆盖。
- 未确认推断被当成项目事实召回。
- 删除、否决或过期后旧知识仍能被检索。
- Provider 参数静默降级、reasoning-only 被标记完成或 API Key 进入知识库。
- 以 Obsidian 打开成功、单元测试或 Mock 结果替代真实跨模块验收。
