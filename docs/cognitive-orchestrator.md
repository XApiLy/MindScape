# MindScape 认知能力编排器

> 状态：概念设计  
> 最近更新：2026-08-13

## 目标

认知能力编排器负责回答一个持续变化的问题：

> 为了让当前 AI 更好地帮助用户推进此刻的任务，现在应该给它哪些认知能力？

它不替代模型推理，也不规定唯一工作流程。它负责理解任务、选择能力、观察效果并及时调整。

## 为什么不能做关键词路由

“我在开发 NeoCarry”无法直接推导出应该装载代码能力。用户可能正在讨论商业定位、学习 Rust、审查交互、调查竞品或制定发布计划。

只按关键词映射会产生三类问题：

- 装错能力：任务还在定义阶段，却进入代码实现流程。
- 装载过多：大量无关 Skill 挤占上下文并相互冲突。
- 无法适应变化：会话从研究进入执行后，能力仍停留在旧阶段。

## 持续任务模型

编排器维护一份结构化但可随时修正的任务模型：

```text
主目标
当前阶段
当前子任务
期望成果
质量标准
已知事实
假设与约束
未解决问题
相关项目与资料
当前能力组合
能力使用反馈
置信度与证据
```

这份模型是会话状态，不是对用户的永久人格判断。

## 编排闭环

```text
观察新消息和当前状态
→ 推断意图、阶段与缺口
→ 生成候选能力计划
→ 检查相关性、冲突、成本与权限
→ 挂载最小充分能力集
→ 观察回答质量和用户反馈
→ 保留、替换、降权或移除能力
```

前两轮是重要的冷启动窗口，但不是识别终点。任务阶段变化、用户切换目标、导入新资料或直接纠正系统时，都应触发重规划。

## 能力选择标准

每项候选能力至少评估：

- 与当前子任务是否直接相关。
- 是否补足明确的信息或方法缺口。
- 是否与已挂载能力重复或冲突。
- 是否会显著增加上下文和延迟。
- 是否需要读取资料或执行工具。
- 是否能提高预期成果的可验证质量。
- 是否应持续挂载，还是只用于下一轮。

编排器在启动更深层的任务理解或能力评估前，先使用两个指标进行门控：

- **目标相关度**：候选信息或能力是否直接服务当前任务。
- **决策价值**：进一步分析是否可能改变结论、行动、风险判断或能力组合。

高相关但低决策价值的内容可以直接引用或归档，不需要反复解释；低相关但可能包含重大发现的内容可以进入候选线索，等待用户选择或漫游分析处理。

## 能力生命周期

- **建议**：相关但置信度不足，等待用户确认。
- **临时**：只服务当前一步，完成后自动卸载。
- **会话**：在当前阶段持续有效。
- **固定**：由用户明确固定，不被自动卸载。
- **暂停**：保留配置但暂不参与上下文。
- **移除**：不再相关、重复、冲突或效果不佳。

## 透明交互

默认界面只显示一行安静的状态，例如：

```text
正在使用：项目规划、技术调研、决策记录  ·  2 项调整
```

展开后显示：

- 为什么装载。
- 依据了哪句话或哪个项目状态。
- 将影响哪些回答。
- 会读取什么信息。
- 持续多久。
- 如何关闭或替换。

透明不等于每次都弹窗。低风险认知能力可以按用户策略自动装载；读取型和执行型能力遵循更严格的权限策略。

## 质量反馈

编排器不只依赖点赞和点踩。它还可以从以下信号判断能力是否有效：

- 用户接受、修改或否决了成果。
- 用户反复补充同一类缺失信息。
- 回答是否达到约定的成果结构。
- 工具调用是否成功并提供有效证据。
- 用户是否手动移除或固定某项能力。
- 后续事实是否推翻了此前判断。

这些反馈优先改进当前项目与当前用户的能力选择，不直接把未经确认的推断固化为永久偏好。

## MVP 边界

第一版先实现：

1. 从前两轮生成任务模型。
2. 从有限能力目录中选择最多三到五项认知能力。
3. 展示选择理由、置信度和生命周期。
4. 允许用户固定、移除和替换。
5. 在目标明显变化时重新规划。
6. 保存每次能力变化及其原因，便于调试与评估。

第一版不尝试自动生成任意新 Skill，也不让认知编排器未经授权调用有副作用的工具。

## 需要验证的指标

- 用户手动移除能力的比例。
- 用户主动固定建议能力的比例。
- 能力装载后补充说明和返工是否减少。
- 无关能力占用的上下文成本。
- 任务阶段变化后的重新识别速度。
- 相比不编排时，最终成果接受率是否提高。
