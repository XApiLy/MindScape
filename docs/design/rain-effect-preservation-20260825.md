# 雨滴效果保存与双引擎基线

状态：已确认，作为 VIS-008 视觉基线的实现记录。

## 保存的当前方案

当前统一方案以一份 `Raindrops` 水滴模拟同时驱动三个目标：壁纸下方、组件表面、全局最上层。三者共享折射、反射、光学高光和 45 FPS 的材质参数；组件表面通过 SVG 矩形裁剪只作用于可见组件区域，全局最上层通过透明 WebGL 合成作用于整个视口。

- 亮度：`1.02`
- 强度映射：`minRefraction = 48 + intensity * 80`
- 最大折射：`180`
- 阴影 alpha 减项：`4`
- 统一模拟帧率：`45 FPS`
- 组件表面裁剪：`svg-rects` 作为 DOM 参照，并同步下沉为 WebGL `u_clipRects[8]` 片元裁剪，确保两套引擎都能真正只在组件区域输出
- 全局合成补偿：保留同一光学采样，使用目标层专用的颜色混合系数，避免将已捕获的页面再次作为灰色整面覆盖

点击设置面板中的“保存当前方案”会将完整快照写入 `localStorage`：`mindscape-rain-preset-v1`，同时保留当前引擎、天气模式、强度、层级和可见度。

## 两套雨滴引擎

1. **Unified Optical · 统一光学**：当前方案，所有层级使用同一模拟和材质。
2. **Original Weather Effects · 原仓**：以仓库 `rain-renderer.jsx` 的原始不透明合成路径为基准；当选择组件表面或全局最上层时，仅增加透明目标适配，不改变原仓折射采样。透明适配会对捕获背景做中性约束，防止 WebGL/DOM 快照缺失时输出黑色水滴板。

引擎选择写入 `sessionStorage` 的 `mindscape-rain-engine-v1`。切换引擎会重建一次渲染器，但不会因组件层级切换而重建模拟；这样可以保持拖动、输入和层级切换时的响应性。

## 层级契约

层级只改变目标合成位置，不改变水滴形状、折射、反射和高光：

- `environment-underlay`：组件背后，完整场景合成。
- `component-surface`：组件表面，使用组件矩形裁剪。
- `global-overlay`：全局最上层，透明 WebGL 合成，不拦截输入。

## 三条合成链（2026-08-25 重构）

层级不再只是移动同一张 canvas，而是明确选择氛围输入和输出目标。设 `B` 为背景、`C` 为组件渲染、`A` 为当前雨滴引擎、`M` 为组件遮罩：

```text
组件背后： C(A(B))
组件表面： A(C(B), M)
全局最上层： A(C(B), Fullscreen)
```

组件表面与全局最上层现在使用两个独立的透明 canvas/renderer；它们共享同一份水滴模拟，但不共享合成目标。这样切换层级时不会把全局捕获结果、组件裁剪状态或旧引擎状态带到另一个目标。
