# 流式呈现、阅读锁定与会话定位交互规格

状态：M2 后续交互规格（待接线实现）  
提出：创始人  
范围：Chat 阅读视口、运行中回答呈现、画布当前节点定位  
原则：内容和运行状态真实优先，动效只改变呈现，不改变事实

## 1. 要解决的问题

当前 `ChatWorkspace` 在 `run.content` 每次变化时都把阅读容器滚到 `scrollHeight`。这会在用户阅读旧内容、复制内容或回看上文时强行改变视口位置。当前回答文本也是一次性显示已收到的全部 delta，只配有闪烁光标，不是可控的打字式呈现。

本规格将问题拆为两个独立能力：

1. **流式呈现层**：把已经收到的真实文本以有快有慢的节奏呈现出来。
2. **阅读导航层**：让用户明确决定是否跟随最新内容，并可以把当前会话或当前节点吸附定位到可读位置。

两层不能互相越权：呈现层不能改写运行事实，导航层不能在用户阅读时抢夺焦点。

## 2. 流式输出：真实数据与可见文本分离

运行内核继续保存和广播真实的 `rawContent` / `text_delta`，用量、完成、取消、失败和重试都以真实事件为准。前端增加仅用于显示的 `revealBuffer`：

```text
Provider delta
    -> raw stream state（事实、持久化、恢复、复制）
    -> reveal queue（仅展示）
    -> visible answer（阅读视图）
```

禁止用“延迟 Provider 事件”来制造打字效果，也禁止把展示队列当作数据库正文。用户复制、导出、重试、恢复和验收读取的必须是 raw 内容；显示队列只负责当前帧已经露出多少。

### 2.1 有快有慢的节奏

- 使用 `requestAnimationFrame` 或等价的可取消调度器，不使用每个字符创建一个长期 `setInterval`。
- 以 Unicode grapheme/词组为最小分段，不能切断 emoji、组合字符或代理对；中文可按短片段合并。
- 普通文本采用短片段快速露出；换行、句号、问号、感叹号、冒号和代码块边界允许出现很短的自然停顿。
- 当 `reveal queue` 积压时自动加速追赶；积压超过安全阈值时直接批量露出，不能让视觉动画落后于真实流超过一个可感知的长时间。
- `completed`、`cancelled`、`failed` 或组件卸载时必须立即或极短时间内 flush 队列，不能出现“模型已完成但界面还在长时间慢慢打字”的假运行状态。
- `prefers-reduced-motion` 或用户关闭打字效果时，delta 直接可见；不影响流式事件和运行状态。
- 如果思考摘要单独展示，它应拥有独立的展示队列和折叠状态，不得因为思考区域增长而改变正文阅读位置。

### 2.2 状态一致性

展示层必须覆盖以下情况：首 token 前、正常流式、正文为空但有 reasoning、正常完成、用户取消且保留部分内容、异常失败、重新连接/恢复。任何状态下不得用“等待运行恢复”覆盖已经确定的失败或取消状态。

## 3. 阅读视口：默认不抢夺用户位置

阅读容器维护一个明确的 `followMode`，而不是在每个 delta 上无条件滚底。

### 3.1 跟随条件

- 运行开始时，只有当用户本来就在底部附近（建议距离不超过 64px）且没有主动上滑，才进入 `following-latest`。
- 在 `following-latest` 中，新内容可以保持最新回答可见，但只在渲染帧或小批次更新后调整位置，不能每个 Provider delta 都执行平滑滚动。
- 用户滚轮、触摸板、触摸拖动、键盘 PageUp/方向键或拖动滚动条离开底部后，立即进入 `reading-locked`。
- `reading-locked` 时，新回答继续生成、继续落库、继续显示 unread/new-content 提示，但绝不改变 `scrollTop`，也不把页面往下扯。
- 用户手动回到底部附近，可恢复 `following-latest`；也可以通过按钮显式恢复。
- 流式结束时不因完成事件强制跳底。用户在哪儿，就保持在哪儿。

### 3.2 稳定锚点与布局

- 每个 turn 和运行中的回答都有稳定的 `data-conversation-id` / `data-node-id` / `data-run-id` 锚点。
- 未跟随时，回答高度增长不能让上方正在阅读的内容发生跳动；必要时以当前阅读锚点的相对 offset 修正滚动位置。
- 浏览器原生 scroll anchoring 和应用自己的定位逻辑不能同时争夺控制权；实现时应明确 `overflow-anchor` 策略，并用单一控制器管理滚动。
- “新增内容”提示应是浮动控件或视口内状态条，不占用回答正文流，避免它本身造成二次布局跳动。

## 4. “定位到会话”与“磁吸吸附”

“磁吸”定义为**用户主动触发后，目标锚点平滑进入稳定可读位置并停止**，不是系统在后台自动把用户吸走。

### 4.1 阅读视图定位

当运行中且用户处于 `reading-locked` 时，显示“定位到最新”按钮，可附带“有 N 段新内容”提示。点击后：

1. 找到当前运行的回答锚点；
2. 以回答起始位置或当前阅读目标为稳定锚点，平滑滚动到可读区域；
3. 到达目标后进入 `following-latest`，后续流式内容才允许跟随；
4. 用户再次手动上移，立即解除跟随。

按钮文案不能暗示这是强制刷新或重新运行；它只是改变阅读视口。

### 4.2 画布定位

画布保留“定位当前节点”能力，并增加明确的吸附语义：

- 只在用户点击“定位当前节点/当前会话”或从阅读卡片主动跳转时移动画布视口。
- 目标节点平滑居中，保留足够边距；到达后停止，不持续跟随节点文本高度变化。
- 流式内容增长不得改变节点坐标，也不得在后台再次移动相机。
- 运行开始时的自动居中应改为有条件行为：只有用户明确从该节点发起并且当前视图允许自动定位时才执行；否则由用户点击定位。
- 若目标不存在、节点已被过滤或画布尚未测量完成，按钮应保持可解释的禁用/等待状态，不跳到任意节点伪装成功。

### 4.3 两个动作不能混淆

| 动作 | 作用 | 是否恢复流式跟随 |
| --- | --- | --- |
| 定位到最新 | 阅读视图跳到正在生成的回答 | 是 |
| 定位当前节点 | 画布把选中会话节点吸附到视口 | 否；只移动画布 |
| 适配全部节点 | 画布重新计算全局视图 | 否；不改变 Chat 阅读位置 |

## 5. 可访问性和性能约束

- `aria-live` 只宣布必要的状态变化，不能把每个字符都读给屏幕阅读器；正文应按语义片段或完成阶段更新。
- 定位按钮必须可键盘访问，有清晰的 focus、pressed/disabled 状态和中文标签。
- 动效应支持 reduced-motion；低性能设备可直接关闭打字呈现和定位过渡，但保留功能。
- 单次流式运行最多只有一个 reveal scheduler 和一个 scroll controller；切换会话、取消、重试或卸载时必须清理。
- 性能验收关注长回答、快速 delta、用户上滑后持续输出、切换画布/阅读视图和重启恢复，不以动画帧率掩盖数据丢失。

## 6. 验收矩阵

1. 用户在底部发起运行：回答有自然的快慢变化，视口可跟随，停止后不继续假打字。
2. 用户在旧消息中间发起或切回阅读：新 delta 到达时 `scrollTop` 不变，出现“定位到最新/新增内容”提示。
3. 点击“定位到最新”：当前回答平滑吸附到可读位置，之后才跟随；再次上滑立即锁定。
4. 用户复制、导出、取消、失败和重试：读取的是完整 raw 内容，不是尚未露出的显示片段。
5. 思考摘要增长、正文为空、首 token 超时或运行恢复：正文滚动策略不被错误状态污染。
6. 画布中流式回答增长：节点位置和相机保持稳定；点击“定位当前节点”才平滑居中。
7. 开启 reduced-motion、窄屏和低性能模式：仍能阅读、定位、键盘操作，且无强制跳动。

本规格先作为交互与工程边界记录，不等同于新的员工06派单；视觉样式、动效曲线和最终按钮外观仍在创始人直管的视觉方向下确认。功能占位可以沿用现有 UI-HANDOFF-06 规则，但不得修改上述状态语义。
