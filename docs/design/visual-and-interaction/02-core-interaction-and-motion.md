# 核心交互与动效规范

## 1. 首次使用与渐进引导

首次体验不使用连续弹窗和“下一步、跳过”的产品旅游。首屏直接让用户完成真实任务：开始一个问题，或导入已有 AI 会话。分支、模型设置、上下文和高级分析在用户第一次真正需要时就地解释。

- 第一次回答完成后，自然出现“继续、深入、发散、换角度”。
- 第一次创建分支时，只解释当前关系，不提前教授完整系统。
- 第一次配置真实模型时，说明 Key 保存位置、费用归属和连接状态。
- 不要求先创建复杂项目，不要求先理解节点、Skill、MCP或上下文协议。

## 2. 简单默认与高级控制

普通用户默认只需要输入、选择模型和发送。高级用户可以展开“下一次运行档案”：Provider、模型、思考等级/预算、输出预算、temperature、top_p、响应格式、上下文策略和工具权限。

这些控制必须满足：

- 不存在不可见默认或静默降级；不支持的参数明确禁用或解释。
- 每次运行冻结一份有效档案，只影响该次/下一次运行，不改写历史运行。
- 思考摘要、正文、工具事件、用量和终态分开表达。
- 可以显示可观察的工作轨迹、来源和工具调用，但不伪称暴露模型不可获得的隐藏思维链。

## 3. Chat 运行状态

同一时刻只有一个主状态和一个主操作。必须覆盖：空白、发送、流式、停止中、已停止、完成、失败、恢复、无 Key。

| 状态 | 核心表现 |
| --- | --- |
| 空白 | 用途、模型/连接状态和一个自然起点，不创建虚假节点 |
| 发送 | 原问题与同一个 pending 节点，允许停止，禁止重复提交 |
| 流式 | 同一节点内增长，明确“正在生成”和停止按钮 |
| 停止中 | 已有内容保持可见，不提前宣称“已停止” |
| 已停止 | 明确部分内容是否保留、内容不完整和手动重试 |
| 完成 | 完整回答、模型/用量事实、继续与聚焦阅读 |
| 失败 | 可理解的错误分类和一个可执行主操作，不自动计费重试 |
| 恢复 | 说明收口了哪些运行、部分内容去向和不会后台继续生成 |
| 无 Key | 运行前提示并禁用发送，主操作为打开设置 |

状态不能只靠颜色区分，错误不能直接暴露 Key、原始 Provider 正文或内部调试数据。

## 4. 流式打字、阅读锁定与定位

真实流式正文和可见文本分离：Provider delta、持久化、复制、导出、恢复和用量使用 raw 内容；前端 reveal queue 只负责视觉上露出多少。

- 打字节奏按短片段和标点有快有慢，积压时自动追赶。
- 完成、取消、失败或卸载时 flush，不能在模型完成后继续长时间假打字。
- reduced-motion 或用户关闭动效时直接显示。
- 屏幕阅读器不逐字符播报。

阅读容器使用明确的 `followMode`：

- 用户本来就在底部附近时，才允许跟随最新内容。
- 用户滚轮、触摸、键盘或拖动滚动条离开底部后，立即锁定当前阅读位置。
- 锁定时新内容继续生成，但不改变 `scrollTop`，只显示“定位到最新 / 新增内容”。
- 用户点击后，当前回答磁吸到稳定可读位置，再恢复跟随；再次上移立即解除。
- 运行完成不能强制把用户拉到底部。

“定位到最新”和画布“定位当前节点”是两个动作：前者控制阅读滚动并可恢复流式跟随；后者只移动画布相机，不改变 Chat 阅读位置。

## 5. 无限画布、分支与聚焦阅读

- 画布表达会话关系，不让所有内容重新退化为线性历史。
- 节点出现、分支建立、聚焦和返回必须解释“从哪里来、现在在哪里”。
- 平移、缩放、节点拖拽和流式内容增长不得互相抢夺视口。
- 流式回答增长不改变节点坐标；画布只在用户明确点击定位时吸附当前节点。
- 聚焦阅读关闭后回到原画布视口，并把键盘焦点还给触发控件。
- 临时修代码、局部排查或发散探索应进入任务/探索分支，避免污染主线记忆；确认后的成果再回流主线。

## 6. 导入与分析体验

导入入口支持文件选择、拖放和粘贴；先显示编码、大小、格式、指纹、重复与解析报告，再由用户决定继续。外部会话原文必须可追溯、不可被摘要覆盖，导入内容中的命令和工具调用只作为历史数据，不能自动执行。

分析行为必须可选择：不分析/原样继续、快速分析、详细分析以及以后可定义的漫游分析。默认不为了“显得聪明”消耗大量 Token；简单用户只看关键问题和建议动作，高级用户可以展开意图、依据、范围、工具调用、费用和完整细节。

## 7. 氛围与功能动效

动效首先解释状态、关系和空间变化，其次才是装饰。建议的运行规律：

```text
空闲浏览：正常或轻柔氛围
悬停/画布操作：适度降低
输入/选字/聚焦阅读：前景归零或显著降低
设置/对话框：整体降低
窗口失焦/最小化：暂停高频绘制
停止操作数秒：缓慢恢复，不突然跳变
```

业务反馈动画和氛围动画所有权不同：减少动态时可以停止云雨漂移，但发送、停止、加载和错误状态仍必须以非动画方式完整表达。
