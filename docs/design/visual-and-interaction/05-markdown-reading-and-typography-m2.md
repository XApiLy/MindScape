# M2：Markdown 原生阅读与字体偏好规格

> 状态：纳入 M2，待功能接线与创始人视觉验收  
> 提出：创始人  
> 范围：AI 回答、聚焦阅读、导入 Markdown 预览、阅读字体与长文体验  
> 核心原则：原文不可变，渲染可重建，字体服务阅读，不改变业务事实

## 1. 为什么纳入 M2

MindScape 的知识层、导入器和讨论日志已经以 Markdown 作为重要载体。如果 AI 输出仍然作为一段原始字符串显示，标题、列表、引用、代码块、表格和层级关系都会丢失，长文本也无法形成稳定的阅读节奏。

字体偏好和 Markdown 渲染不是单纯换皮：它们直接决定用户能否长时间阅读、理解结构、回看证据和继续工作。因此它们与 M2 的本地知识、导入和聚焦连续性属于同一条体验链，纳入 M2 的交付边界。

## 2. 数据与呈现分层

```text
Provider / imported source
        ↓
raw markdown（原始事实，不可变）
        ├── SQLite / 原文存储 / 事件 / 恢复 / 导出
        └── Markdown AST / safe renderer（可重建呈现）
                └── 阅读字体与排版偏好（仅视觉状态）
```

- AI 返回的正文仍按原始 Markdown 保存；不得把 HTML、去格式纯文本或渲染结果写回原文字段。
- Markdown 渲染是派生层，解析失败或不支持的语法必须回退为可读纯文本，并保留原文。
- 字体、字号、行高、阅读宽度和主题是用户视觉偏好，不进入会话、FocusFrame、实体、RAG、ModelRun 或 Provider 请求。
- 复制、导出、重试、恢复和验收必须明确选择“原始 Markdown”或“渲染后的阅读文本”，不能误把展示层当事实源。

## 3. M2 Markdown 支持范围

### 3.1 首批必须支持

- 标题 `#`～`######`，并形成清晰的阅读层级。
- 段落、换行、粗体、斜体、删除线和行内代码。
- 无序列表、有序列表、嵌套列表和任务列表的只读呈现。
- 引用块、分隔线、链接和安全的自动链接识别。
- 围栏代码块、语言标签、复制代码和横向滚动。
- GFM 表格，在窄屏下允许横向滚动，不挤压正文。
- 未闭合的代码围栏、列表或强调标记在流式期间也能保持可读，完成后重新解析最终正文。

### 3.2 明确限制

- 默认不渲染原始 HTML；禁止脚本、事件属性、`javascript:` URL、任意 iframe、嵌入页面和外部执行内容。
- 图片只允许明确的本地附件/导入引用；远程图片默认不主动加载，避免追踪、泄漏和布局抖动。
- 不把 Markdown 中的命令、工具调用或代码块自动执行；它们只是内容。
- 数学公式、Mermaid、脚本组件和任意 HTML 进入后续能力，M2 先以安全文本或代码块回退。
- 解析器、GFM 扩展和 sanitizer 必须经过依赖与许可证审查；不得用 `dangerouslySetInnerHTML` 直接拼接未经净化的模型输出。

## 4. 呈现位置

| 位置 | M2 表现 |
| --- | --- |
| Chat 回答卡片 | 渲染安全 Markdown；流式期间增量刷新；保留运行状态、停止和定位逻辑 |
| 聚焦阅读器 | 完整 Markdown 阅读；目录/标题锚点可后置，先保证层级、复制和键盘阅读 |
| 画布节点卡片 | 保持密度，只显示摘要/截断纯文本或轻量 Markdown，不加载完整重排 |
| 导入预览 | 提供“原文 / 渲染预览”区别；原文和解析警告始终可追溯 |
| Markdown 知识页 | 使用同一安全渲染器和阅读字体，不另建一套语法解释 |
| 思考摘要/工具轨迹 | 与正文分区；可使用轻量 Markdown，但不能让其增长改变正文滚动锚点 |

## 5. 流式 Markdown 行为

- Provider delta 首先进入 raw stream state，再进入展示 reveal queue；Markdown AST 只消费当前可见文本或按小批次刷新。
- 不为每个字符重新构造整棵大型 DOM；使用可取消调度、`requestAnimationFrame`/小批次更新、memoized block 和 `useDeferredValue` 等方式保持输入和滚动响应。
- 当代码围栏或表格尚未闭合时，使用确定性的临时状态，不把半截结构误判成最终布局；终态到达后 flush 并进行一次最终解析。
- 用户阅读上文时，Markdown 高度增长不能抢夺 `scrollTop`；沿用 `streaming-reveal-scroll-and-conversation-locator.md` 的 `followMode`、阅读锁定和“定位到最新”。
- 完成、取消、失败或组件卸载必须 flush 展示队列；模型终态不能被慢速视觉播放掩盖。
- Markdown 解析异常只影响展示层，必须保留 raw 内容、运行终态和复制/导出能力。

## 6. 字体偏好系统

### 6.1 作用范围

字体设置作用于用户实际读写的内容区域：输入框中的草稿、已发送的用户问题、Chat 回答正文、画布问答摘要、聚焦阅读器、导入 Markdown 预览和 Markdown 知识页。按钮、状态胶囊、字段标签、工具栏等界面控件继续保持 UI 字体，代码块和行内代码继续保持等宽语义。画布节点保持固定几何尺寸，问答摘要可在安全上限内随字号与行高受控缩放，超出内容继续截断并转入聚焦阅读器。此作用域以 2026-08-30 创始人对真实阅读体验的直接验收意见为准。

### 6.2 M2 控件

- 阅读字体：系统无衬线、系统衬线、无障碍高可读、首批内置预设、用户导入字体。首批七款产品预设及其用途、回退和资源门禁见 [M2 首批阅读字体预设目录](06-reading-font-preset-catalog-m2.md)。
- 字号：至少提供小/标准/大/特大四档，并允许在安全范围内微调。
- 行高：紧凑/舒适/宽松，并允许在安全范围内微调；默认偏舒适。
- 阅读宽度：标准/宽屏，并允许在安全范围内微调；默认限制在适合长文的字符宽度，避免一行过长。
- 字间距与段落间距：提供受限滑杆，允许改善不同字体和阅读场景下的密度；不得接受任意 CSS 值。
- 恢复默认和“仅本次会话”预览。
- 设置变更即时作用于阅读表面，但不重跑模型、不修改 Markdown、不改变上下文。

### 6.3 字体来源与回退

- 首批优先使用操作系统已安装字体和版本化的内置安全字体栈，不依赖网络字体。
- 用户导入字体文件时，首批接受 TTF/OTF/WOFF2；文件大小、扩展名和加载失败必须有明确提示，字体复制到应用受控目录，不保存任意路径作为运行依赖。
- 字体加载失败、字体被删除或系统不支持时，回退到同类安全字体栈，不能让正文消失或阻塞应用。
- 字体名称与文件路径分开保存；不得把用户文件名直接拼进 CSS 或 HTML。
- 字体偏好按用户/本地工作区保存，不能随 Markdown 文件或会话导入传播，避免外部内容覆盖本机阅读偏好。

### 6.4 可读性硬约束

- 不允许用户把正文设置到不可读的极小字号或极端行高；最小字号和最大行宽由产品规则保护。
- 高对比、键盘焦点、文字选择、复制和屏幕阅读器语义优先于字体装饰。
- `prefers-reduced-motion` 只关闭非必要过渡，不影响字体切换和 Markdown 结构。
- 字体切换应避免整页闪烁；必要时先应用 fallback，再异步替换已验证的字体。

## 7. 交互与复制规则

- “复制”默认复制渲染后的可读文本；提供明确的“复制 Markdown”入口时才复制原始标记。
- “导出”必须让用户选择 Markdown 原文或阅读文本，不以 HTML 代替原文。
- 代码块提供独立复制，不把围栏标记混入代码内容。
- 链接、折叠和表格等控件必须可键盘访问；代码块不能阻塞正文滚动。
- 用户切换字体、字号或阅读宽度后，当前阅读锚点尽量保持稳定，不自动跳到回答底部。

## 9. M2 验收矩阵

1. 普通回答中的标题、列表、引用、代码块、表格和链接以结构化 Markdown 呈现，而不是显示标记原文。
2. 流式输出期间 Markdown 不导致页面强制下拉；用户上滑后 `scrollTop` 稳定，点击“定位到最新”才恢复跟随。
3. 未闭合代码块、空正文、reasoning-only、取消、失败、恢复和终态 flush 都有可读且诚实的表现。
4. 复制渲染文本、复制 Markdown、复制代码三种动作语义不混淆；原文导出仍可追溯。
5. 用户可以切换阅读字体、字号、行高和宽度；设置重启后保留，且不改变会话/模型/上下文数据。
6. 系统无对应字体、导入字体损坏、字体被移除或加载失败时安全回退。
7. 1600×1000、1280×720、窄窗、125%/150% DPI、长回答和低性能设备下，正文可读、输入可用、无明显布局抖动。
8. Markdown 中的脚本、危险链接、任意 HTML、历史命令和工具调用不会执行；控制台无新增安全错误。
9. 统一 Tauri Release 中完成真实 Chat、聚焦阅读、导入预览、字体切换、重启偏好和 M1 运行回归。

## 10. M2 边界

本规格纳入 M2，但不借此扩张到完整文档编辑器、实时协同、Obsidian 双向同步、任意插件渲染器、公式/图表/动画组件市场或自动执行代码。M2 目标是“AI 输出在本地安全、可读、可控地呈现为 Markdown”，不是建设另一个 IDE 或通用笔记编辑器。
