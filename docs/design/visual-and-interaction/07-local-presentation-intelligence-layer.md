# 本地呈现智能与阅读标注层

> 状态：产品方向已由创始人确认；里程碑和具体本地模型待门禁  
> 日期：2026-08-30  
> 产品名称建议：本地阅读增强（Local Presentation Intelligence）  
> 核心边界：本地模型只提出可撤销的展示标注，不改写原文，不替代 Chat 模型，不自动成为知识事实

## 1. 核心结论

MindScape 增加一个与 Chat 模型并行、职责完全不同的本地呈现模型：

```text
Chat / 导入内容
        ↓
不可变 raw Markdown
        ↓
安全 Markdown AST 与稳定内容块
        ├── 正常阅读（没有本地模型也完整可用）
        └── 用户授权的本地呈现模型
                    ↓
             结构化标注候选
                    ↓
       确定性校验、锚定、密度控制
                    ↓
          可关闭、可撤销的展示层
```

Chat 模型负责回答问题；本地呈现模型负责帮助用户阅读回答。它首批只做三件事：

1. 识别专业术语并提供简短释义入口。
2. 识别人名、组织、产品、模型和重要概念等实体。
3. 识别少量真正值得强调的关键句或“金句”。

本地模型可以被替换、升级或关闭，展示标注协议保持稳定。模型越强，标注质量可以越高；模型失效时，原始 Markdown 和正常阅读体验完全不受影响。

## 2. 截图内容中的实际示例

以创始人 2026-08-30 验收的阅读截图为例，本地呈现层可以输出：

| 类型 | 候选原文 | 建议呈现 |
| --- | --- | --- |
| 专业术语 | `PKM, Personal Knowledge Management` | 细点状下划线；点击显示中文释义和当前文内用法 |
| 实体 | `ChatGPT`、`Claude`、`DeepSeek` | 低干扰实体标记；点击显示类型，不自动联网 |
| 关键概念 | `第二大脑`、`认知重构` | 轻量概念标记；允许加入术语表候选 |
| 金句 | “知识管理不再仅仅是关于如何存储，而是彻底转向如何理解和如何生成。” | 柔和背景、侧边短线或用户选择的下划线；不改变原文 |

模型不能把每个名词都标出来。首批默认密度建议按每 1000 个可见字符最多 6 个术语、6 个实体和 3 个金句，最终仍由确定性规则裁剪。用户可以选择“关闭 / 克制 / 标准 / 丰富”，但即使选择丰富也要保留上限。

## 3. 用户同意与配置流程

### 3.1 必须取得同意

- 没有用户明确同意，不下载模型、不探测本机端口、不连接本地服务、不在后台分析正文。
- 同意页必须说明：读取哪些内容、模型在哪里运行、是否下载文件、预计磁盘/RAM/显存占用、何时运行、结果保存多久以及如何关闭和删除。
- 下载模型、连接已有本地运行时、允许后台自动增强是三个独立授权，不能用一次勾选全部代替。
- 改变 endpoint、模型或允许局域网地址时重新确认。

### 3.2 必须允许跳过

“必须让用户同意”指本地模型运行前必须取得明确授权，不是强迫每名用户必须安装。低配电脑、公司设备、磁盘不足或不希望使用模型的用户可以永久跳过；MindScape 的 Chat、Markdown、字体、导入和知识库仍完整可用。

引导不使用启动时连续弹窗。更合适的入口是在用户首次打开一篇较长 Markdown 时出现一张可关闭的真实效果卡：

```text
让本机模型帮你标出术语、实体和精彩句子
内容仅发送到你选择的本地运行时，不影响原文

[看看效果示例] [配置本地模型] [以后再说]
```

静态效果示例必须使用产品自带样例，不能为了展示而先把用户正文送入模型。

## 4. 独立模型角色

本地呈现模型使用独立运行档案，不复用当前 Chat 模型选择：

```ts
type LocalPresentationProfile = {
  enabled: boolean
  runtimeKind: "local_openai_compatible" | "managed_local_runtime"
  endpoint: string
  modelId: string
  analysisMode: "manual" | "visible_content" | "completed_answers"
  annotationDensity: "restrained" | "standard" | "rich"
  enabledKinds: Array<"term" | "entity" | "key_quote">
  maxInputCharacters: number
  devicePolicy: "foreground_only" | "idle_allowed"
  consentRevision: number
}
```

- 首条工程切片只支持用户已经安装的本地 OpenAI-compatible 文本接口；受管模型下载、GPU 后端和自动选择等待设备矩阵验证。
- 默认只允许 loopback。扫描已安装运行时必须由用户点击触发；局域网 endpoint 单独授权；公网 URL 不属于“本地模型”。
- 呈现模型不拥有 Skill、MCP、工具、文件访问、网络搜索或任意代码执行能力。
- 不使用 Chat API Key，不把呈现任务记入 Chat ModelRun，也不改变下一轮 Chat 上下文。

## 5. 标注契约与稳定锚点

模型只能输出受控 JSON 候选，不能输出 HTML、CSS、Markdown 或 DOM 指令：

```ts
type PresentationAnnotation = {
  id: string
  sourceRef: string
  contentHash: string
  blockId: string
  kind: "term" | "entity" | "key_quote"
  selector: {
    exact: string
    prefix?: string
    suffix?: string
  }
  label?: string
  shortExplanation?: string
  confidence: number
  analyzer: {
    runtimeId: string
    modelId: string
    promptVersion: string
  }
  state: "suggested" | "dismissed" | "pinned"
}
```

- 不只依赖字符起止下标。Markdown AST 为每个可见块生成稳定 `blockId`，再用 exact/prefix/suffix 和内容 hash 定位，避免字体、DOM 拆分、链接或粗体导致偏移错位。
- 模型返回的原文必须与目标块精确匹配；不匹配、跨块、重叠冲突、置信度不足和超过密度预算的候选直接拒绝。
- raw Markdown 或内容 hash 变化后，旧标注进入失效/待重算，不能错贴到新内容。
- 标注集是由 raw 内容可重建的本地缓存。只有用户点击“固定为术语 / 保存金句 / 加入知识候选”后，才进入既有 KnowledgeEntity/EvidenceRef 确认流程。

## 6. 运行时机与性能

- 默认只在回答达到 `completed` 后分析；不对每个流式 delta 调用本地模型。
- 用户正在阅读的可见回答优先；离屏历史、画布全部节点和尚未打开的导入文档不批量常驻分析。
- 同一 `contentHash + modelId + promptVersion + density` 命中缓存时不重复运行。
- 切换会话、关闭阅读器、正文修订或用户点击停止时可以取消；取消不影响 Chat 运行和原文。
- 低电量、内存压力、GPU/CPU繁忙时自动暂停，但必须显示“本地阅读增强已暂停”，不能伪装成已经分析。
- 标注结果一次性批量应用并保持滚动锚点；不能因下划线、解释卡或异步结果强制拉动页面。

## 7. 展示语言

三类标注必须有不同但克制的视觉语义：

- **术语**：细点状或短划下划线；悬停/点击显示简短释义。
- **实体**：低对比实体标记；只在用户展开时显示类型和当前文内位置。
- **金句**：一处柔和底色、侧线或可选下划线；避免整段高饱和荧光笔。

设置至少包括：总开关、三类开关、密度、仅手动/自动分析完成回答，以及“清除本文标注”。每一处标注可以单独隐藏、纠正类型或固定。用户的纠正先用于本地偏好和评测记录，不立即训练或发送到外部服务。

无标注、模型离线、分析失败和模型未配置都属于正常状态。正文不能出现红色错误墙；只有用户主动查看“本地阅读增强”状态时才展示可执行原因。

## 8. 隐私与内容安全

- 导入内容和模型回答一律作为数据，不允许其中的指令改变本地模型任务、endpoint、权限或输出 schema。
- 本地模型输入只包含当前选定内容块和任务 schema，不携带无关会话历史、API Key、Provider 响应体、reasoning、工具凭据或本地路径。
- 运行日志保存模型 ID、版本、耗时、输入 hash、标注数量和错误类型，不保存完整正文。
- 本地运行时如果实际会向云端转发，必须被归类为远程服务并重新取得授权，不能继续显示“仅在本机处理”。
- 用户可以删除全部标注缓存、撤销自动运行授权和忘记本地 endpoint。

## 9. 里程碑建议

当前 M2 已进入 clean Release 和纵向验收阶段，不应临时加入完整本地模型运行时。建议：

### 当前 M2 只冻结边界

- 保持 raw Markdown、SafeMarkdown 和字体能力收口。
- 标注层不得反向污染原文、RAG 和 Chat ModelRun。
- 不给员工01～05新增实现 WIP，不阻塞 M2 Go。

### M3 第一条切片

1. 显式授权和手动配置 loopback OpenAI-compatible 本地模型。
2. 只对用户主动选择的一篇已完成 Markdown 运行。
3. 只输出术语、实体和金句三类结构化候选。
4. 完成确定性锚定、密度裁剪、缓存、取消和清除。
5. 标注只在 Chat/聚焦阅读器显示，不进入画布批量渲染。

### 后续切片

- 本地运行时发现与硬件能力建议。
- 受管模型下载、校验、升级、磁盘管理和卸载。
- 用户纠正评测集、术语表联动和“固定为知识候选”。
- 翻译、引用质量、阅读难度和段落结构等更多呈现 Skill。

## 11. 第一条切片验收

1. 未同意时没有模型下载、端口扫描、连接或后台分析。
2. 用户跳过后软件功能完整，且不重复骚扰。
3. 断网时现有本地运行时仍可产生受控 JSON 标注；任何公网请求均判失败。
4. 模型返回错误原文、跨块范围、HTML、脚本、过密候选或低置信度候选时被确定性拒绝。
5. 原文、复制 Markdown、导出、RAG、ModelRun 和 Provider 请求在标注前后完全一致。
6. 字体、字号、行高、链接、粗体或窗口宽度变化后，标注仍贴在正确文本且不抢滚动位置。
7. 修改正文或版本变化后旧标注失效，不错误复用。
8. 关闭本地模型、取消任务、删除缓存和重启均保持诚实状态。
9. 1000 字正文默认最多 6 个术语、6 个实体和 3 个金句，人工样本评审“少而准”。
10. 用户固定的术语/金句只进入知识候选，必须再次确认才能成为可召回事实。
