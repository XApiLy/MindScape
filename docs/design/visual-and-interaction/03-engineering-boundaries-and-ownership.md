# 工程边界、性能与职责

## 1. 当前实现与目标视觉架构

| 层面 | 当前正式 `desktop/` | 已确认目标/原型方向 |
| --- | --- | --- |
| 桌面与本地能力 | Tauri v2 + Rust | 保持 |
| UI框架 | React 19 + TypeScript + Vite | React 19继续作为当前正式路线 |
| 业务界面 | 可访问DOM、CSS；画布节点为DOM/SVG | DOM继续拥有输入、阅读、菜单、节点卡片和焦点 |
| 视觉合成 | 当前深色CSS表面 | PixiJS v8 + WebGPU负责背景、氛围和有明确收益的图形层 |
| Shader | 尚未完整进入生产 | WGSL主路径，GLSL/WebGL安全回退 |
| 3D | 未进入正式工程 | Three.js仅为Drei云或明确3D场景懒加载，不进首包 |
| 样式/动效 | 现有CSS | Tailwind CSS v4、Motion One属于候选目标，不代表已经接入 |
| 数据 | SQLite；业务状态在Rust/React契约中 | LanceDB属于知识检索层，不属于视觉系统 |

不能把目标架构说成当前已经完成，也不能因为当前使用DOM就否定后续Pixi/WebGPU方向。

## 2. 运行边界

```text
AppearancePreferences
  背景 + 全局材质 + 区域覆盖 + 天气/云 + 可访问性偏好
        ↓ 纯解析
AppearanceRuntimeState
  输入/选字/阅读/对话框/失焦/性能/设备信号
        ↓
BackgroundRoot → AtmosphereAdapter → SurfaceAdapter → 可访问DOM内容
```

- DOM拥有输入、文本选择、阅读、表单、按钮、菜单、焦点和节点业务操作。
- Pixi/WebGPU拥有背景、氛围和可证明有性能/画质收益的图形合成。
- Shader只接收时间、尺寸、视觉预设、强度和退让参数，不接收 Prompt、消息、Provider、API Key、工具结果或运行终态。
- 视觉层不成为业务状态机；动画结束不能制造“运行完成”。
- SQLite、LanceDB和上下文语义不进入Shader或材质解析器。

## 3. 性能、降级与安全

- Classic Opaque、静态背景和完整业务控件必须始终可用。
- reduced-motion停止非必要连续运动；高对比模式优先不透明表面。
- 低性能模式卸载天气和Drei Canvas，并让Liquid Glass回退Opaque；不是只设透明后继续渲染。
- WebGPU/WebGL、纹理、第三方组件或设备失败只关闭对应视觉层，不阻断Chat与画布。
- 窗口失焦或最小化时暂停高频绘制，恢复后不补跑历史帧。
- React状态不能跟随每一帧动画更新；视觉ticker与业务React状态分离。

已发现并修正的原型性能风险：Ybouane不能把静态/独立环境视为每帧动态截图源。环境重采样走适配器节流，普通状态约250ms，输入/设置/阅读约700ms，并按面板轮转，不能恢复全区域同帧重绘。Drei必须动态加载并本地化纹理；React Weather必须清理RAF/interval并复用GPU资源。

## 4. 设计与实现职责

| 层级 | 负责人 | 边界 |
| --- | --- | --- |
| 产品体验决策 | 创始人 | 最终确认方向、取舍和审美体验 |
| 规格与范围治理 | 总经理/产品负责人 | 整理交互规则、验收、依赖和越界审阅 |
| 最终视觉与交互 | 员工06，创始人直管 | 视觉语言、原型、动效参数、磁吸/节奏体验和真实应用视觉验收 |
| 无限画布工程 | 员工03 | 节点/边、视口、定位、性能和画布测试 |
| Chat与工作区工程 | 员工04 | Chat、模型设置、运行状态、错误、流式阅读和前端集成 |
| Provider事件验证 | 员工05 | 流式、reasoning/content、用量、取消/失败/恢复夹具与真实矩阵 |
| 领域/数据接口 | 员工01/02 | 领域事实、SQLite、恢复和IPC；阻止视觉反向改变内核 |

员工06不由总经理或PEC派发具体任务；PEC只记录创始人已经直接安排的事项、确认/否决、交接、结果和风险。

## 5. 占位 UI 与交接

员工02、03、04可以先实现必要按钮、面板、表单、预览、加载、空白和错误状态，以验证真实功能链路；不得等待最终视觉而阻塞开发，也不得自行建立新视觉体系。

占位入口需要保留 `UI-HANDOFF-06`：位置、用途、数据/IPC、正常/加载/空白/错误/停止/恢复状态、键盘与焦点、可替换范围，以及不可改变的领域字段、IPC、测试选择器和安全边界。

标准流程：

```text
创始人提出体验方向
→ 员工06形成原型/动效样例并与创始人确认
→ 总经理检查范围和工程影响
→ 员工03/04按模块实现真实行为
→ 员工06在同一真实Tauri Build中做视觉与交互验收
```

## 6. 生产门禁

独立浏览器原型只能证明视觉方向和第三方来源可以组合，不能替代正式生产验收。进入 `desktop/` 前至少需要：创始人明确开工、范围/依赖评估、许可证与本地资产处理、Classic回退、键盘/焦点/文字选择、目标尺寸、减少动态、低性能、设备丢失和统一Tauri Release Build证据。
