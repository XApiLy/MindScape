# MindScape 视觉与交互设计工程师职责

> 状态：员工06席位已建立，待填写具体人员  
> 日期：2026-08-18  
> 汇报关系：直接与创始人沟通；由产品负责人控制范围；与员工03、员工04共同落地

## 1. 为什么需要这个角色

MindScape 的核心差异不仅来自会话图和模型能力，也来自用户如何进入会话、理解分支、观察 AI 状态、操作无限画布并感受到产品品质。

员工03负责画布工程正确性与性能，员工04负责 Chat、工作区和运行状态。视觉、动效和交互不能长期由两人分别临时决定，否则会形成两套体验语言，也会让工程负责人同时承担设计探索和底层稳定性压力。

因此设置员工06“视觉与交互设计工程师（Design Engineer）”。这个角色不是增加审批流程，而是持续产出可验证的界面、交互和动效方案，并在工程落地后负责视觉验收。

## 2. 核心职责

- 建立 MindScape 的视觉语言：色彩、字体、层级、间距、圆角、阴影、图标和状态样式。
- 设计 Chat、无限画布、模型设置、导入预览和首次使用的完整交互流程。
- 设计有明确意义的动效：节点生成、分支展开、聚焦阅读、流式状态、视图切换、错误与恢复。
- 制作可点击原型、关键帧或短视频，让创始人在工程开发前能够真实判断体验。
- 把确认后的方案转成组件状态、交互规则、动效参数和响应式要求，供员工03、04实现。
- 在真实 Tauri 应用中做视觉与交互验收，不能只验收静态设计稿。
- 维护设计决策、组件规范、动效规范和已确认版本，减少口头意见丢失与反复返工。

## 3. 与创始人的实时沟通

该角色直接与创始人沟通，不由工程人员转述设计意图。固定流程如下：

```text
创始人表达体验方向或参考
→ 设计工程师快速形成原型 / 动效样例
→ 与创始人实时确认
→ 记录已确认、待调整和明确否决项
→ 输出工程规格
→ 员工03 / 04实现
→ 设计工程师在真实应用中验收
```

沟通要求：

- 工作日保持一个直接沟通渠道，重要方案不跨多人转述。
- 关键交互开发前确认，不等实现完成后才首次展示。
- 高频调整使用截图、短录屏或可点击原型沟通，避免只用抽象文字。
- 每次确认后形成简短决策记录：确认内容、否决内容、仍待验证内容和影响模块。
- 任何改变 V1 功能范围、数据语义、安全边界或里程碑的建议，必须交由产品负责人评估，不能通过视觉稿直接进入开发。

## 4. 与员工03、员工04的边界

| 角色 | 最终负责 |
|---|---|
| 视觉与交互设计工程师 | 体验意图、视觉规范、交互行为、动效规格和视觉验收 |
| 员工03 | 无限画布实现、节点与边投影、视口、性能和画布测试 |
| 员工04 | Chat、工作区、设置、运行状态、错误体验和前端集成测试 |
| 员工01 | 领域与上下文语义，阻止设计反向改变内核事实 |
| 产品负责人 | 产品范围、优先级、里程碑和最终冲突裁决 |

设计工程师可以直接实现局部 CSS、动效原型和纯表现组件，但不得绕过员工03、04修改画布或 Chat 的业务状态，也不得让动画状态成为领域数据源。

## 5. 动效与特效原则

- 动效首先解释关系、状态和空间变化，其次才是装饰。
- 节点出现、分支建立、聚焦与返回必须帮助用户理解“从哪里来、现在在哪里”。
- 流式输出不能造成全图跳动，特效不能干扰阅读、输入和停止操作。
- 所有重要动效需要明确持续时间、缓动、打断、重复和降级规则。
- 支持减少动态效果的系统偏好；不能只靠颜色或动画表达关键状态。
- 特效必须有性能预算，在目标设备上验证后才能进入正式版本。
- 不为了“高级感”引入 3D、重型粒子、复杂着色器或与 Chat 无关的视觉系统。

## 6. 各里程碑交付

### M1：真实 Chat Alpha

- 整理现有 UI，冻结第一版视觉基线和组件状态语言。
- 补齐发送、流式、停止、失败、恢复、选中节点和模型状态的交互规范。
- 与员工03、04完成真实 Chat Alpha 的视觉验收，不阻塞后端运行与 Provider 开发。

### M2：会话导入 Alpha

- 完成导入入口、文件预检、完整性报告、预览和原样继续的可点击流程。
- 设计长历史进入画布时的定位、折叠与来源表达。

### M3：多模型与接续分析 Beta

- 完成模型切换、原样 / 快速 / 详细分析、范围费用提示和证据查看体验。
- 统一不同模型、来源、分析层和运行状态的视觉表达。

### M4～M5：发布与内测

- 完成首次使用、空状态、错误、窄窗、键盘、减少动态效果和一致性验收。
- 根据真实内测问题修复理解障碍，不在发布阶段扩大视觉功能面。

## 7. 验收标准

- 创始人能在开发前通过原型判断关键体验，而不是等代码完成后返工。
- 员工03、04拿到的规格包含正常、加载、空白、错误、停止、恢复和边界状态。
- 同一状态在画布、Chat、设置和导入流程中使用一致语言。
- 动效可以打断、降级，不影响停止、输入、阅读和恢复。
- 视觉验收基于真实应用和目标窗口尺寸，不以静态截图代替。
- 设计调整有记录，工程师不需要依赖聊天记忆猜测最新版本。

## 8. 不承担的职责

- 不负责产品范围和路线决策。
- 不负责会话图、ContextSnapshot、数据库和 Provider 契约。
- 不替员工03、04承担全部前端业务实现。
- 不以个人审美阻断已经满足规范的实现。
- 不把 AI IDE、本地 Agent、社区或其他 V2 能力通过设计稿提前带入 V1。
