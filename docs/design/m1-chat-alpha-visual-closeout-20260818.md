# MindScape M1 Chat Alpha 视觉与交互收口稿

> 提交人：员工06（视觉与交互设计）  
> 日期：2026-08-18（UTC+8）  
> 状态：待创始人确认；正式产品代码未按本稿修改  
> 范围：M1 真实 Chat Alpha，不包含导入器、多 Provider、新画布能力或整体品牌重构

## 1. 交付结论

当前 M1 已有可保留的骨架：对话列表、画布/阅读双视图、底部输入器、节点化回答和聚焦阅读。本轮不需要整体重设计，需要的是把“当前发生了什么、系统是否还在工作、用户现在能做什么”在九个关键状态中说清楚。

收口原则是：

- 一个时刻只有一个主状态和一个主操作，不让用户从多处小字推测系统状态。
- “停止”是明确的状态过渡，不是瞬时切换图标：正在停止 → 已停止，并明确部分内容是否保留。
- 失败、无 Key 和恢复不混成一个笼统的“出错了”；每种状态都要告诉用户事实和下一步。
- 流式文本、部分文本、失败原因和恢复结果只是底层事实的投影，不自行制造“已完成”。

## 2. 保留 / 修改 / 删除 / 后置

### 保留

| 现有表现 | 保留理由 | M1 边界 |
|---|---|---|
| 左侧对话列表 + 中央工作区 + 底部输入器 | 心智模型稳定，适合持续追问 | 不改布局架构 |
| 画布 / 阅读双视图 | 兼顾思路结构与长文阅读 | 保留一个稳定节点投影 |
| 发送按钮在运行期转为停止 | 操作位置连续，不需要重新寻找 | 补充“停止中”反馈 |
| 停止后保留部分内容 | 忠实反映真实运行，避免用户损失 | 必须明确标记不完整 |
| 节点状态标识和聚焦阅读 | 支持从全局切换到长文消化 | 关闭后返回原节点与原视口 |
| Provider/运行环境明示 | 能避免把预览误当真实运行 | 收敛为可理解的连接状态 |

### 修改

| 问题 | 修改规格 | 优先级 / 建议负责人 |
|---|---|---|
| 深色界面的次要文字、边框和空态对比度过低 | 将状态、可操作元素和辅助文案分成三档；可操作元素不使用最低对比度 | P0 / 员工04，员工06验收 |
| 发送、流式、停止中的反馈分散 | 输入器右侧按钮保持位置，同时在输入器内显示“正在发送 / 正在生成 / 正在停止”；停止请求期不提前显示“已停止” | P0 / 员工04 |
| “已停止”与部分内容的关系不够醒目 | 在节点内追加一条不完整说明，保留内容不用失败色整块染红，主操作为手动重试 | P0 / 员工04 |
| 失败文案容易只呈现技术原因 | 先告知“本次没有完成 / 不会自动重试”，再给一个与错误分类一致的操作：重试或打开设置 | P0 / 员工04，员工05确认事实 |
| 无 Key 在发送后才暴露会造成错误预期 | 输入区在运行前就显示“需要配置 Key”，发送禁用，唯一主操作为打开设置 | P0 / 员工04、05 |
| 启动恢复如只用短暂 toast，用户无法核对结果 | 使用可关闭的恢复通知，说明收口了几个运行、部分内容是否保留；对应节点标记“已恢复” | P0 / 员工04，员工02确认事实 |
| 节点生成时空画布到内容的过渡缺少连续性 | 发送后立即创建同一个 pending 节点占位，后续 delta 在原节点内增长；禁止终态时再突然多出第二个节点 | P0 / 员工03、04 |
| 聚焦阅读的退出可预期性需纳入验收 | `Esc`、关闭和“返回画布”均恢复原视口与触发按钮焦点 | P1 / 员工03、04 |

### 删除（从 M1 主流程中移除，不代表立即删代码）

| 表现 | 删除理由 |
|---|---|
| 空白页面中不可用的“导入”入口或预告 | M1 不做导入器，禁用操作会与首次发送竞争注意力 |
| 用户不能采取行动的内部运行编号、原始 Provider 正文和调试详情 | 主界面只留用户可理解的分类；详情只进入脱敏诊断面板 |
| 同一状态在顶部、节点、输入器和 toast 中完全重复的长文案 | 保留“节点事实 + 当前操作反馈”；全局通知只处理跨节点事件，例如恢复和凭据配置 |
| 失败后自动发起可能计费的重试 | 必须由用户明确触发，并在重试前保留上一次事实 |

## 3. M1 九态矩阵

| 状态 | 进入条件 | 用户必须看到 | 主操作 | 节点 / 持久化结果 | 离开条件 |
|---|---|---|---|---|---|
| **空白** | 新对话无节点 | 一句用途说明、示例问题、模型与连接状态 | 输入第一个问题 | 不创建虚假节点 | 提交有效问题进入发送 |
| **发送** | 用户提交问题，尚未收到首个 delta | 原问题、“正在发送”、稳定的 pending 节点 | 停止 | 同一运行只有一个占位节点 | 首 delta 进入流式；取消进入停止中；错误进入失败 |
| **流式** | 收到首 delta | 持续增长的文本、“正在生成”、明确停止按钮 | 停止 | 在同一节点内更新部分文本，不创建新节点 | 完成事件进入完成；取消进入停止中；异常进入失败 |
| **停止中** | 用户发出取消，尚未得到终态确认 | “正在停止”、已接收的文本保持可见、按钮暂时不可重复触发 | 等待（无第二主操作） | 运行仍非终态；不先行宣称已停止 | 确认 cancelled 进入已停止；取消失败回到流式并显示非阻断警告 |
| **已停止** | 收到唯一 `cancelled` 终态 | “已停止”、保留的部分内容、“内容不完整”说明 | 手动重试 / 继续提问 | 唯一取消终态；部分文本可重启投影 | 用户明确发起新运行 |
| **完成** | 收到 `completed` | 完整回答、已完成标识、模型和可用时的用量摘要 | 继续提问 / 聚焦阅读 | 节点和用量事实稳定，重启后投影一致 | 新问题进入新一次发送 |
| **失败** | Provider/网络/超时/异常断流收口为 `failed` | 用户可理解的错误分类、本次未完成、不会自动重试、不显示 Key/原始响应 | 重试或打开设置，只能有一个主操作 | 唯一失败终态；是否保留部分文本按真实事实表示 | 用户明确重试或完成配置 |
| **恢复** | 启动扫描发现残留非终态并完成收口 | 恢复通知、受影响运行数、部分内容去向、“不会继续后台生成” | 查看节点 / 手动重试 | 没有永久 pending；节点、运行、事件投影一致 | 用户关闭通知；恢复节点保留可追溯标记 |
| **无 Key** | 当前 Provider 没有可用凭据 | “需要配置 Key”、凭据存储边界、禁用的发送按钮 | 打开设置 | 不创建 ModelRun 或失败节点 | 凭据配置并验证成功后回到空白/就绪 |

### 矩阵的共同验收条件

- 状态不只靠颜色区分；每个终态都有明确文字。
- 读屏在状态变化时只播报必要摘要，不逐 delta 播报。
- 主操作可通过键盘访问；焦点环对比明确；模态阅读关闭后焦点回到触发按钮。
- 对 `prefers-reduced-motion: reduce` 停用非必要动画，不用动画时长表达业务状态。
- 窄窗口下输入器、停止按钮和错误主操作不得移出可视区。

## 4. 可点击原型

入口：`docs/design/prototypes/m1-chat-alpha-closeout/index.html`

原型覆盖：

1. 点击“填入示例问题”，再发送：观察空白 → 发送 → 流式 → 节点生成 → 完成。
2. 流式期点击红色停止按钮：观察停止中 → 已停止，以及部分文本保留。
3. 等待回答完成后点击“聚焦阅读”：观察对话框、返回路径和焦点恢复。
4. 使用原型顶部的“无 Key”、“失败”、“恢复”快捷入口核对非成功状态。

这份原型只模拟视觉与交互，不调用 Provider、不读写 SQLite、不接触 API Key，也不作为 Node/ModelRun 事实源。
