# MindScape 分层视觉与氛围系统设计基线

> 状态：设计基线 v0.4；已确认渲染框架、自定义片元着色器与 VIS-008 原仓来源，未通过门禁不得进入生产实现  
> 确认日期：2026-08-19  
> 决策关系：创始人确认体验方向，员工06维护设计规格，员工03/04按职责落实工程  
> 适用范围：MindScape 桌面端整体背景、卡片与控件材质、氛围特效及其可访问性降级
> 执行计划：[分层视觉与氛围系统完整执行计划](../engineering/layered-visual-system-execution-plan-20260819.md)

## 1. 核心目标

MindScape 的界面不是一张统一底色上的平面控件集合，而是一个分层、可组合的视觉空间：最底层的背景建立环境，悬浮在其上的功能卡片建立工作区域，卡片内部的按钮、输入框和标签继续拥有各自表面。用户既可以得到传统软件的清晰、克制，也可以选择通透、动态和有氛围感的体验。

当前确认的总体模型是：

```text
最终视觉结果
= 背景主题
× 组件材质
× 氛围主题
× 区域级覆盖
```

四项互相独立，不允许把“用了壁纸”等同于“必须透明”，也不允许把“纯色主题”等同于“只能使用不透明组件”。

## 2. 分层模型

```text
L0    背景层
      纯色、渐变、图片、视频、兼容的 Wallpaper Engine 壁纸

L0.5  背景内氛围
      属于环境本身的雨、云、雾、光影、雪、尘埃等

L1    全局环境微调层
      亮度、色温、饱和度、轻微模糊；完全可调，也可以关闭

L1.5  空间氛围层
      位于背景与主卡片之间，强化空间深度但不承担信息可读性

L2    主功能卡片
      侧边栏、阅读区、编辑区、设置区、节点信息等；承担主要局部遮蔽与可读性

L2.5  卡片材质效果
      局部反射、折射、模糊、染色、高光和边缘表现

L3    直接控件表面
      按钮、输入框、标签、选项和工具控件，各自拥有明确表面与状态

L4    临时浮层
      菜单、对话框、提示和聚焦阅读

L4.5  前景氛围
      只在少量边缘和非工作区域出现，默认不能持续穿过关键内容
```

关键修正：`L1` 只做轻微、可关闭的全局环境调整。真正保证文字和控件可读性的暗化、遮蔽和模糊应主要由 `L2` 卡片局部完成。不能为了上层内容可读而长期压暗整张壁纸。

视觉嵌套建议最多保持三层：主表面、模块表面、直接控件表面。更深的装饰嵌套容易让界面臃肿，必须有明确交互意义才能增加。

## 3. 背景主题

### 3.1 颜色主题

- 支持纯色和渐变色。
- 黑、白、灰是基础选择，但颜色体系不局限于中性色。
- 背景只负责建立环境，不决定上层组件透明度。

### 3.2 壁纸主题

- 支持静态图片、视频和可兼容的本地动态壁纸。
- 计划通过本地检索发现 Steam Wallpaper Engine 的安装位置与用户订阅目录。
- 壁纸浏览结果应提供标题、预览、类型、本地来源和兼容状态；同时保留手动选择本地路径的入口。
- 图片、视频及部分 Web 壁纸较容易兼容；Wallpaper Engine 的 Scene 或 Application 类型可能依赖其运行时，不能提前承诺全部可嵌入。
- 不兼容、缺失或启动失败时，必须安全回退到用户指定的颜色主题，不能影响工作区启动和业务数据。

Wallpaper Engine 接入属于背景来源适配，不得侵入会话、画布或 Provider 的业务状态。

## 4. 组件材质

组件材质是独立于背景主题的第二条轴。

### 4.1 不透明材质

- 纯色表面。
- 渐变表面。
- 高对比、常规桌面软件表面。
- 适合长时间阅读、低性能设备、简洁偏好和复杂壁纸。

### 4.2 透明材质

- 毛玻璃。
- Liquid Glass。
- 染色玻璃。
- 其他具有透明、折射或高光表现的材质。

透明不是单一开关。模糊、透明度、染色、噪点、折射、高光和边缘强度应由材质预设统一协调，避免用户得到一组互相冲突的参数。

### 4.3 合法组合

以下四种组合必须全部成立：

- 颜色背景 + 不透明组件。
- 颜色背景 + 透明组件。
- 壁纸背景 + 不透明组件。
- 壁纸背景 + 透明组件。

### 4.4 区域级覆盖

用户先选择一个全局材质预设，再按区域覆盖。首批候选区域包括：

- 侧边栏。
- 画布与节点卡片。
- 长文阅读区。
- 消息编辑器。
- 设置与对话框。

例如，侧边栏可以使用 Liquid Glass，长文阅读区保持不透明，编辑器使用低透明度毛玻璃。区域覆盖是已确认方向；是否继续细化到每一个 `L3` 控件仍待原型验证。

## 5. 氛围主题

氛围是独立于背景与材质的第三条轴，不是壁纸的附属开关。候选主题包括关闭、雨、云雾、雪、尘埃、光影、水波焦散、极光/色流，以及与当前壁纸匹配的自定义氛围。

天气类界面的关键价值不是粒子数量，而是空间感：云层可以位于多个深度，以缓慢、宽阔、低频的方式移动；少量前景云可以偶尔穿过大型非交互文字，但信息卡片与工作内容必须稳定。玻璃表面可吸收背景的色温，使环境与工作区属于同一个空间。

氛围的设计原则是：

> 背景创造世界，卡片建立工作区，氛围让世界活起来；当用户开始思考和工作时，氛围必须退到工作之后。

## 6. 氛围安全规则

1. **内容优先**：文字、输入框、菜单和关键按钮不能被长时间遮挡。
2. **专注退让**：输入、聚焦阅读、文本选择、设置操作和对话框打开时，前景氛围自动减弱。
3. **中心安静、边缘活跃**：效果优先出现在卡片间隙、画布空白和窗口边缘。
4. **低频优先**：优先缓慢、宽阔、偶发的运动，不持续制造高密度粒子噪声。
5. **不表达业务状态**：天气和装饰效果不能成为成功、失败、运行中等状态的唯一载体。
6. **可降级**：失去焦点、窗口最小化、省电模式、低性能设备或系统“减少动态效果”开启时暂停或降低效果。

建议的专注衰减顺序：

```text
空闲浏览
→ 正常氛围

鼠标或画布交互
→ 前景效果轻微降低

输入、阅读或文本选择
→ 前景效果显著降低，中心区域保持安静

停止操作数秒
→ 氛围缓慢恢复，不能突然跳变
```

区域约束建议：编辑器始终保持安静；聚焦阅读默认关闭前景效果；画布空白区允许更明显的云雾和粒子；节点卡片周围形成低干扰区；侧边栏可有轻微反射，但标签上不持续落雨；任何对话框打开时整体氛围降低。

## 7. 控制方式

首层设置保持简单：

- 关闭。
- 轻柔，建议作为默认强度。
- 沉浸，由用户明确选择。

高级设置候选：总强度、速度、云量、雨雪密度、前景强度、内容避让、失焦暂停、输入/阅读自动降低，以及可选的声音与音量。

“视觉天气”应可离线使用。真实天气同步可以后置为可选数据源，不能成为氛围系统的基础依赖。

## 8. 渲染与桌面框架

创始人确认以下为视觉系统的目标工程框架：

```text
Tauri v2 + Rust                    桌面壳、本地能力、安全边界
React 19 / SolidJS + Vite          可访问控件与低频界面状态
PixiJS v8 + WebGPU                 主视觉画布、背景与氛围合成
DOM + WebGPU hybrid                输入、按钮、阅读等仍由DOM承担
Custom fragment shaders           云、雨、光影、材质与颜色合成
Three.js (lazy, optional)          仅在明确3D场景中按需加载
Tailwind CSS v4 + Motion One       生产样式与界面动效候选基线
SQLite + LanceDB, Rust Native      本地数据与AI检索，不进入Shader层
```

职责边界：DOM拥有可访问控件、文本选择、输入与焦点；PixiJS拥有背景、氛围和可证明有收益的图形合成；Three.js没有明确3D需求时不得进入首包；Tauri/Rust拥有本地文件发现和Wallpaper安全边界。React/Solid更新不能跟随每一帧动画，Shader时间推进由渲染器ticker负责。

### 8.0 example 融合基线

`example/` 是能力参考与独立原型来源，不是生产代码的复制目录。创始人已冻结 VIS-008 的来源职责：Ybouane LiquidGlass 只做 Liquid Glass，Glacé 只做毛玻璃，React Weather Effects 只做天气，Drei `Cloud` 只做云。完整来源快照、参数、许可证和验收证据见 [VIS-008 选定视觉源基线](selected-visual-source-baseline-20260820.md)。

| 职责 | 选定原仓 | MindScape 落点 |
| --- | --- | --- |
| Liquid Glass | `liquid glass/liquidglass-main` / Ybouane | L2/L3 Liquid Glass Surface，保留折射、色差、Fresnel、边缘高光和圆角/Z曲率 |
| 毛玻璃 | `liquid glass/glace-main` / Glacé | L2/L3 Frosted Surface，保留尺寸位移、边缘折射、blur、bezel、profile 和 sheen |
| 天气 | `react-weather-effects-master` / React Weather Effects | L0.5 雨雪雾天气适配器与强度预设 |
| 云 | `drei-master` / `Cloud`、`Clouds` | L0.5 Drei 广告牌云层，独立懒加载与低性能卸载 |

Three.js 官方体积云、Joshbrew Realtime Clouds、Shuding Liquid Glass、Specy 和其他早期近似实现仍保留在原仓对照台，作为被排除或后置参考，不得重新混入已冻结职责。`example/雨雪粒子系统.txt` 没有确认许可证，只能参考思路，不能复制代码。所有移植均须保留版权/许可证，并由交接包记录具体文件来源。

独立原型 `tools/selected-visual-baseline` 直接 alias 四个选定原仓源文件，仍保持现有 MindScape 左侧会话区、中央节点、右侧阅读区、底部编辑器和外观设置入口；这证明的是原仓效果在统一布局中的组合，不代表 `desktop/` 已获生产开工门禁。

### 8.1 自定义片元着色器

- WebGPU主路径使用WGSL，WebGL回退使用GLSL，二者保持相同视觉语义。
- 首批内置Shader覆盖云层、雨线、光影、局部染色与材质合成；每个效果必须受强度、专注退让、减少动态和设备策略控制。
- Uniform只允许视觉输入，如时间、分辨率、材质参数、氛围预设和退让系数。
- Shader不得接收Prompt、会话内容、Provider、API Key或运行成功/失败等业务事实，也不得成为状态机。
- 首批“定制”指项目内审核、版本化的预设及安全参数；不开放用户粘贴任意WGSL/GLSL，不下载或执行第三方Shader代码。
- 编译、设备丢失或性能异常时，独立关闭Shader层并回退到静态背景/Classic Opaque，Chat与Canvas继续可用。

### 8.2 雨滴合成层级系统（重构确认）

雨滴不因“组件后”或“全局最上层”而改变视觉算法。两种位置都使用同一个 `RainField` 模拟、同一个雨滴水面纹理和同一个光学材质；层级系统只负责选择合成目标与遮罩范围。

```text
RainField（一次模拟 / 一次更新）
        │
        ├── RainMaterial（统一折射、反射、高光、透明度）
        │
        ├── environment-underlay  → 壁纸/环境层之上、UI 卡片之下
        ├── component-surface     → 仅裁剪到组件表面、位于常规 UI 之上
        └── global-overlay         → 完整 DOM 场景之上、pointer-events:none
```

目标描述包含 `id`、`composite`（under/over）、`scope`（viewport/element）和层序，不再在 shader 内为全局模式维护另一套视觉分支。组件表面目标通过实时 SVG 裁剪矩形接入，不复制模拟或材质；设置面板不属于雨滴组件裁剪范围。

全局目标使用低频 DOM 场景快照作为光学背景，输出透明的局部光学增量；它不能输出第二张完整背景。环境目标可以输出完整合成表面，但使用的雨滴 mask、反射和折射参数与全局目标完全一致。雨滴层永远不拦截输入。

性能约束：每个窗口只运行一个雨滴模拟；三个合成目标只允许一个处于运行状态；目标切换不重建模拟、图片缓存或 WebGL program；纹理上传保持单张水面纹理与固定帧率；场景快照只在 DOM/窗口发生有效变化时更新，不进入每帧循环。

2026-08-25 原型验证：连续切换三种目标时底层 weather canvas 保持同一实例；组件表面正确生成 5 个可见组件裁剪区域；全局目标恢复 viewport 范围；三种目标均报告 `shared-optical`，运行期无 WebGL warning。

## 9. 状态与工程边界

视觉配置应与业务状态分离，概念上至少包含以下四组：

```text
Appearance
├── background     背景类型、来源与轻微环境调整
├── material       全局材质与区域覆盖
├── atmosphere     主题、强度、专注衰减和性能策略
└── accessibility  减少动态、高对比及降级偏好
```

- 切换主题不能修改会话、节点、模型运行或 Provider 状态。
- 氛围引擎不能成为业务事实源。
- 壁纸加载失败不能阻塞聊天与画布。
- 生产实现前必须验证窗口缩放、低性能模式、GPU 占用、焦点变化和减少动态效果。

## 10. 已确认、明确避免与待确认

### 已确认

- 背景与 UI 分层，卡片和直接控件拥有各自表面。
- 背景主题、组件材质、氛围主题彼此独立。
- 同时服务喜欢传统不透明界面和喜欢透明、动态效果的用户。
- 支持全局材质加区域级覆盖。
- 全局环境调整轻微且可关闭，主要可读性遮蔽位于卡片局部。
- 氛围非常重要，但必须在工作开始时主动退让。
- Wallpaper Engine 采用本地发现思路，并显式处理兼容性与回退。
- 主画布采用PixiJS v8/WebGPU与DOM混合架构，自定义片元着色器是正式能力，Three.js保持按需可选。

### 明确避免

- 用整屏重遮罩掩盖壁纸，再称为壁纸主题。
- 把透明材质和壁纸主题绑定。
- 所有层级都使用高强度玻璃、反射和粒子。
- 特效持续穿过输入区、菜单或关键工作内容。
- 将所有 Wallpaper Engine 壁纸宣传为完全兼容。
- 用天气效果表达业务状态或让视觉配置进入领域数据。

### 待创始人确认

1. 氛围由用户独立选择，还是允许根据壁纸自动推荐并保持可覆盖。
2. 第一阶段只做视觉，还是同时加入环境声音。
3. 首批三种氛围是否采用云雾、雨、光影/尘埃。
4. 前景效果能否偶尔穿过大型非交互文字，还是严格只停留在边缘。
5. 第一阶段区域覆盖只到 `L2` 主卡片，还是允许单独覆盖 `L3` 控件。
6. 是否先以独立可点击原型验证，再修改生产界面。

### 原型执行默认值

为使原型不因待决策项停滞，执行计划暂按以下默认值推进：氛围可随壁纸推荐但保持独立可覆盖；首阶段不做声音；首批验证云雾、雨和光影；轻柔模式的前景效果只在边缘，沉浸模式只允许偶尔穿过大型非交互标题；区域覆盖首批到 `L2`，`L3` 继承；先做独立原型再申请生产范围门禁。

这些是原型默认值，不自动升级为最终产品决策。创始人在可点击原型中确认或修改后，本节与执行计划同步更新。

## 11. 建议的首个原型范围

在进入正式重构前，建议做一个不连接业务数据的独立可点击原型，同时展示：

- 颜色背景与壁纸背景切换。
- 不透明、毛玻璃、Liquid Glass 三种材质切换。
- 侧边栏、阅读区、编辑器的区域覆盖。
- 云雾与雨两种氛围。
- 输入和聚焦阅读时的自动退让。
- 减少动态效果与性能降级开关。

原型只用于确认层级、材质、可读性和氛围平衡，不代表已授权重构生产代码。
