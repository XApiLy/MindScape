# UI 工程先行占位与员工06交接规范

> 状态：立即生效
>
> 适用对象：员工02、03、04的功能开发；员工06的视觉与交互后续接管

## 目的

功能开发不能因为最终视觉还未确定而停住。员工02、03、04可以先把必要的界面入口和状态画出来，先验证真实功能链路；员工06再在不改变内核和业务状态的前提下完成视觉、交互和动效升级。

占位 UI 是“工程承载层”，不是设计稿，也不是员工06的任务派单。

## 占位 UI 可以做什么

- 放置按钮、表单、面板、标签、列表、预览和错误区域。
- 接入真实 IPC、加载状态、取消、失败、恢复和空状态。
- 使用现有 CSS、现有组件结构和最少必要布局。
- 补充键盘操作、焦点、ARIA 语义、测试选择器和响应式最低保障。
- 用简单的状态色和文本说明当前功能是否已接入。

## 占位 UI 不可以做什么

- 不建立新的视觉语言、主题、组件体系或全局 Token。
- 不引入新的特效、Shader、Pixi、复杂动效或整体 CSS 重构。
- 不改变领域契约、IPC 名称、数据状态和错误语义来迁就外观。
- 不把未接入的功能画成已完成，不伪造解析、检索、模型调用或成功结果。
- 不因等待员工06而阻塞功能开发，也不通过 PEC 给员工06派发任务。

## `UI-HANDOFF-06` 注释模板

在 TSX/HTML/CSS 入口附近添加以下信息；不同语言使用对应的注释语法：

```text
UI-HANDOFF-06
位置：例如 Chat 编辑区右上角 / 画布节点详情 / 导入预览底部
用途：这个区域解决什么用户动作或状态观察问题
数据/IPC：数据来自哪个状态、查询或 Tauri 命令
状态：正常、加载、空白、错误、停止、恢复分别如何表现
交互约束：键盘、焦点、取消、禁用和可访问性要求
可替换范围：员工06可以替换哪些结构/样式/动效
不可改变：领域字段、IPC、业务状态、测试选择器和安全边界
```

注释应靠近实际入口，不要只写在 PEC 或单独的设计文档里。员工06接管后，可以删除或更新注释，并在自己的 PEC 中记录交接结果。

## 交接验收

员工02、03、04提交占位 UI 时，PEC 必须说明：

1. 占位区域在哪里，服务哪个功能。
2. 已接入哪些真实状态，哪些仍是禁用或待接入。
3. `UI-HANDOFF-06` 注释所在文件和位置。
4. 员工06替换表现层时不能改变的接口。
5. 已完成的自动化测试和未完成的视觉验收。

员工06的后续验收必须在真实 Tauri 应用中完成，不以静态截图替代运行状态验证。
