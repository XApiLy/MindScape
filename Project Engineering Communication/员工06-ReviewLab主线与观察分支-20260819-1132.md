- 新增观察分支删除：只有已结束构建的分支可删；主线和构建中分支由服务端强制拒绝。

## 实现与证据

### 版本模型与服务端

- `tools/review-lab/lib.mjs`：增加 `main | branch` 轨道校验、旧版本主线默认值和“只有非构建中分支可删”判定。
- `tools/review-lab/server.mjs`：新增 `POST /api/quick-build` 和 `DELETE /api/versions/<id>`。随时编译固定使用 `preview`，自动命名、标记项目负责人并进入原有串行队列。
- 删除前同时检查：版本存在、`track=branch`、非 `queued/building`、解析后绝对路径仍位于 `runtime-data/versions/` 内。删除只作用于该版本归档目录。

### 界面

- `tools/review-lab/public/index.html` / `styles.css` / `app.js`：左侧新增随时编译按钮，时间线分为永久保留的员工主线和可删除的观察分支。
- 观察分支选中时，顶部和右侧都明示轨道身份，右侧出现独立删除区；主线不渲染删除入口。
- 对比选择器为每个候选版本增加 `[主线]` / `[分支]` 标识，避免在讨论中混淆。
- `tools/review-lab/README.md`：写明双轨含义、GUI/API 用法、删除范围和原生能力边界。

## 验证结果

- Review Lab 单元测试：9/9 通过，新增主线不可删、分支构建中不可删、分支终态可删门禁。
- `node --check server.mjs` 和 `node --check public/app.js`：通过。
- 真实 API 闭环：随时编译创建观察分支，在原构建队列中由 `queued → building → ready`，`sourceChangedDuringBuild=false`，预览可打开。
- 真实删除门禁：对主线发起 DELETE 返回 HTTP 400 和“员工确认主线不可删除”；对已就绪分支返回 HTTP 200，归档和列表记录消失，7 个历史主线全部保留。
- Playwright 真实 UI 闭环：点击“随时编译”创建分支，等待可评审，确认删除按钮可用，接受二次确认后删除；最终分支数为 0、主线数仍为 7。
- 1600×1000 实际渲染检查：双轨标题、观察分支版本、MindScape 预览、分支删除区和右侧元数据同屏正常。

## 契约、数据、安全与恢复影响

- 未修改 `desktop/`、Frozen V1 契约、SQLite schema、Provider、凭据或恢复逻辑。
- Review Lab `track` 只是本机视觉归档分类，不是 Git 分支、产品会话分支或业务真相。
- 随时编译不读取 API Key，归档预览继续使用浏览器 Mock 运行时。
- 观察分支删除是显式、不可从 Review Lab 恢复的归档删除；前端二次确认和服务端轨道/状态/路径检查均必须通过。

## 风险与阻塞

- 随时编译是轻量前端观察，不能代替员工 `full` 主线版本对 Provider、SQLite、凭据、恢复和原生窗口的验收。
- 同一时刻多次点击会进入同一串行队列，不会并发覆盖产物；构建等待是预期行为。
- 暂无阻塞。
