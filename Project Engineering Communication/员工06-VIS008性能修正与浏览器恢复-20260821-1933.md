## 问题与定位

创始人反馈浏览器卡成 PPT。真实浏览器 1280×720 测量确认：

- 默认 Ybouane + React Weather + Drei Cloud 组合：约 `7 FPS`，平均帧间隔约 `142ms`。
- 关闭天气后仍约 `18 FPS`。
- 同时关闭天气和云层后约 `66 FPS`。
- Classic Opaque、无天气/云：约 `239 FPS`。

瓶颈不是 React DOM，而是 Ybouane 检测到环境层 `data-dynamic` 后，对侧边栏、两个节点、编辑器、阅读区和设置浮层全部玻璃区域每帧重复截图和 WebGL 合成。

## 已实施修正

- 保留 Ybouane、React Weather Effects、Drei Cloud 原仓实现，不复制或改写其 Shader。
- 去掉静态壁纸、天气 Canvas 和 Drei Canvas 的 `data-dynamic` 标记，避免把独立环境动画强制升级为 Ybouane 全区域每帧重绘源。
- 通过 Ybouane 官方 `markChanged()` 接口对环境采样节流：空闲 `250ms` 一次；输入、设置和聚焦阅读时 `700ms` 一次。
- 低性能模式仍直接卸载天气/Drei Canvas，并让 Ybouane 区域回退 Classic Opaque。
- 重新构建成功，服务已恢复在 `4200`。

## VIS-008 性能顶级优化复测（2026-08-21）

创始人要求“性能顶级但不能损失画面质感”。先以游戏引擎常用的固定预算、增量更新、稳定 GPU 资源和生命周期回收原则复测，再实施以下不改画质参数的优化：

- Ybouane 不再用一次全局 `markChanged()` 让六个玻璃区域同帧重绘，而是按 `glassSet` 逐面板轮转标记。空闲态每个面板仍保持 `250ms` 更新周期，输入/设置/阅读态仍保持 `700ms` 周期；视觉时间采样不变，只消除同帧突发。
- React Weather 原仓保留雨滴数量、纹理和 Shader；移除每帧 `Float32Array` 全屏几何上传、uniform location 重复查询和碰撞 `slice()` 临时数组，水滴图使用一次分配、后续 `texSubImage2D`。RainRenderer/Raindrops 增加绑定 RAF、停止/恢复和卸载清理，避免旧页面实例继续占用 GPU/CPU。
- Drei 保留原 DPR、`Cloud` 段数、体积、透明度与速度；云 Canvas 关闭无收益的 MSAA，启用高性能 GPU 提示和视锥裁剪；氛围退让时切换 demand loop，内容重新可见时恢复 always loop。
