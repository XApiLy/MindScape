## Review Lab 的核心用途

Review Lab解决的是跨对话、跨时间和跨员工的指代歧义：

```text
创始人打开一个真实历史版本
→ 将界面操作到希望讨论的状态
→ 点击“指向界面细节”并点击具体位置
→ 写明状态、细节名称和希望讨论的问题
→ 获得视觉引用ID与深链接
→ 把ID发给员工06
→ 员工06读取同一版本、坐标、元素和说明后继续讨论
→ 需要工程落实时，把同一引用转给员工03、04或对应员工
```

构建历史的价值是保证引用不会因为下一次界面更新而漂移；不是要求员工围绕代码提交做评审。

## 创始人与员工06如何使用

1. 打开 `http://127.0.0.1:4178`。
2. 在左侧选择当前版或任意历史版本。
3. 在内嵌软件中操作到希望讨论的真实界面状态，例如“正在流式”“停止失败”“节点刚生成”或“恢复后”。
4. 点击顶部“指向界面细节”，再点击具体按钮、节点、文本、边或空间位置。
5. 填写：
   - 当时的界面状态。
   - 这个细节是什么。
   - 希望讨论、修改或确认什么。
6. 保存后工具生成类似 `UI-260818095751-2CB5` 的视觉引用，并自动复制。
7. 在当前对话中把引用ID或完整引用粘贴给员工06；员工06据此读取同一视觉上下文，不依赖模糊截图描述。

## 其他员工如何读取创始人指向的细节

### 深链接

复制的引用自带链接，打开后自动进入对应历史版本并高亮锚点。

### CMD / PowerShell

```powershell
cd D:\Project\MindScape\tools\review-lab
npm run context -- UI-260818095751-2CB5
```

命令输出：版本名称与ID、横纵坐标、当时界面状态、对应元素、指向人、细节名称、讨论内容和可打开链接。

员工Agent需要结构化上下文时使用：

```powershell
npm run context -- UI-260818095751-2CB5 --json
```

### HTTP

```text
GET http://127.0.0.1:4178/api/anchors/UI-260818095751-2CB5
```

员工拿到引用后应先复述自己理解的视觉问题，再决定由员工06产出视觉规格，还是由员工03、04或对应领域员工落实。不得只凭坐标猜测业务语义。

## 版本如何进入 Review Lab

版本编译仍由员工明确确认后触发，但它是视觉讨论的准备步骤：

- GUI：“添加可讨论版本”。
- 交互命令：`npm run mark`。
- Agent参数：`npm run mark -- --title ... --author ... --summary ... --focus ... --preview`。
- Git显式Trailer：`Review-Lab: preview`或`Review-Lab: full`。
- 本机HTTP：`POST /api/versions`。

普通文件修改、普通提交和普通PEC替换不会自动构建。大部分UI讨论使用`preview`；只有原生窗口、真实Provider、凭据、SQLite、崩溃恢复和里程碑才使用`full`。
