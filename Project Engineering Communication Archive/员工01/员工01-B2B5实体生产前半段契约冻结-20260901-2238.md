## 本次关闭的 B 编号

### B2/B5：关闭“只有候选处理后半段、全新数据库无法生产首条实体”的契约缺口

- 新增 `mindscape.import-knowledge-proposal.v1`，把 `ImportSource/Revision/ImportedMessage → source-grounded proposal → user review → KnowledgeEntity` 冻结为独立领域边界。
- `ImportGraphProjection.analysisPolicy` 继续为 `disabled`：导入只保存原文；模型/确定性规则分析必须由用户显式触发，不允许导入后自动分析、自动计费或自动写入知识。
- Provider/规则只能返回 ordinal、建议 kind/name/aliases 和 Kernel 提供的 message ID；proposal、EvidenceRef、entity ID、scope、status、revision、generator 和时间全部由 Kernel 决定。
- Proposal 在审核前不是 KnowledgeEntity，不得进入 FTS/VectorIndex、Vault、Context Compiler 或 `promoteRefs`；Confirm/Reject 必须显示来源，不能把模型输出伪装成事实。
- Conversation proposal 确认后创建 `confirmed/revision=1` 实体；Active FocusFrame proposal 确认后创建 branch-local `candidate/revision=1` 实体，使其真实接入现有“候选选择 → generation receipt → Close → 四动作”。`inferred` 不由用户确认命令伪造。
- requestId/decisionId 分别冻结幂等重放与异请求冲突；Confirm 必须原子提交 review receipt、KnowledgeEntity、EvidenceRef、Vault 和索引，Reject 不创建实体或派生物。

## 完整状态链与不变量

1. 用户导入原文：只落 immutable import bundle，绝不隐式分析。
2. 用户显式选择来源并请求建议：Kernel 校验 source/revision/hash/message/scope，持久化 request receipt 后才运行模型或规则。
3. Kernel 把受限 suggestion 转成带真实 EvidenceRef 的 immutable proposal；模型不能写知识表。
4. 用户 Confirm/Reject：可修改 kind/name/aliases，但不能替换证据或 scope；同 decisionId 重试不重复建实体。
5. Conversation Confirm 进入已确认检索；FocusFrame Confirm 只生成 candidate，不能注入 Context Compiler。
6. FocusFrame candidate 继续复用员工02～04已接通的 selection/generation/Close/four-action/restart 后半段，禁止绕过正式回流决策。
