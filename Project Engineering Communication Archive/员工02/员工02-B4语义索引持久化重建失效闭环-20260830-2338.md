- `semantic_rebuild_rejects_stale_source_and_survives_restart`：KnowledgeEntity → source hash → SQLite v15 原子替换 → 旧 source 拒绝 → 当前向量提交 → 关闭/重开数据库 → Provider semantic retrieval，最终候选携带同一模型 provenance。该证据跨实体、SQLite、恢复和检索投影，不是单一向量算法测试。

## 契约、数据、安全与恢复变化

- schema version：`14 → 15`。员工01需评审新增索引状态表及“内容更新=stale、否决/删除=移除派生记录”的领域边界。
- 新的全量 replace 是 compare-current-source 后提交；不会接受旧 revision 生成的 source hash，也不会在失败时先删除现有记录。
- 不记录模型输入正文、Key、Authorization 或下载响应；状态表只保存模型标识、维度、状态和时间。
